# 描述
- 会话列表里部分 Codex 会话标题是首条消息被错误截断后的残片: 同一批会话出现 `status`、`atus/status`、`tus` (2026-07-10 本机实测截图, 根目录分组下 2026/5/29-31 的 gpt-5.5 会话)。`atus/status`、`tus` 显然是 `status` / `xxx/status` 的前缀被截丢, 推测标题提取从 rollout 首条消息切片时偏移量计算有误 (概念锚点: codex 会话解析器的标题提取逻辑)。

# 重现步骤
- 本机存在 Codex CLI 历史会话 (rollout jsonl), 首条输入为短命令样式文本 (如 `status`)。
- 打开 Berth 会话页, 观察标题列。

# 预期结果
- 标题完整呈现首条用户输入 (或其截断加省略号), 不出现掐头去尾的残片。

# 实际结果
- 出现 `atus/status`、`tus` 等首部丢失的残片标题。

# 解决方案
- 定位 codex 会话标题提取的切片逻辑 (疑似按字节/固定偏移去前缀), 改为按消息结构取完整文本后再做长度截断; 用真实 rollout fixture 补回归测试。
