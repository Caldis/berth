# friction: 正交的设计层次被当成互斥方案, 反复另起炉灶

- action: 2.0-design
- date: 2026-06-23
- task: GH-150 R2 (docs/works/2026-06-23-gh-150-widget-height-tiers)

## 现象
大需求探索 (overview 加高度档 → 完全自定义 dashboard) 中, Agent 反复推翻前一个方案换新的: 内容密度档 → 否决换全数值引擎 → 把内容方案整个丢掉退化成 height:100% + overflow 截断。用户两次当场纠正"不要总是另起炉灶""我们之前讨论的列表式高度方案, 在 dashboard 引擎下应该是融合的"。

## 根因
把两个正交层次当成互斥竞争方案: 布局引擎 (widget 占多大格子, 容器问题) vs 内容自适应 (widget 在格子里显示什么, = 列表式高度方案)。这两个是上下游, 不是二选一。引擎给尺寸, 内容自适应填充。Agent 每次用一个否决另一个, 把内容层粗暴退化成"拉伸+截断", 丢掉内容智能。

## 怎么做 (下次遇到布局/UI 大改)
1. 先分层再提方案: 区分"容器/布局"层 vs "内容/渲染"层, 几乎总是正交、上下游, 不是竞争方案。换布局范式 不等于 废弃内容方案。
2. 换范式时显式自问: 上一个方案是被替代, 还是降为下游一层? 本例内容密度方案降为引擎"层2 内容自适应", 一点不丢。
3. 提新方案前先列上一轮哪些成果可复用, 默认复用非推翻。01-ANALYSIS 的 16 widget 弹性分级跨三个版本始终有效。
4. 用户说"另起炉灶""应该融合"时立即停换方案, 转入分层整合, 不要再抛新方案。
