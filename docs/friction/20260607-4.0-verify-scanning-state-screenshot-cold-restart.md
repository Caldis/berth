# 工程摩擦记录

> 关联: GH-110 P4.6 (扫描进度可视化 hover 弹层 verify)

## 发生阶段
4.0-verify (UI 瞬态加载/扫描态截图验收)

## 现象
要给"扫描中"弹层 (仅 `state==='scanning'` 时可见) 截图, 第一次冷启动捕到了, 但想换个
阶段重拍时改用 CDP `page.reload()` 重新触发扫描 — 结果弹层根本不出现 (`best=null`)。
原因: 主进程 `AgentAssetRuntime` 是单例且带 per-project 快照缓存 (P3.2), reload 只重挂
渲染层; 渲染层 `useAssetRuntime` 一启动就拿到 `status==='ready'` 的热快照, 不再触发
refresh, 于是没有 scanning 态, 边栏指示器 ready+无错时又自动隐藏 → 无从 hover。

## 工程师介入动作
`pnpm dev:agent stop <id>` 后重新 `start` 冷启整个 app (主进程 runtime 清空), 第一次
冷扫描才有 scanning 态; 截图脚本从 CDP connect 起就高频轮询 `[data-testid=...-trigger]`,
一出现立即 hover + 等 `[data-testid=...-panel]` + 截图, 抢在扫描结束前命中。

## 应沉淀的上下文或规则
- 验收任何"仅在扫描/加载进行中可见"的瞬态 UI: **必须冷重启 agent 实例**, 不能靠
  `page.reload()` — 主进程扫描 runtime 是热单例 (快照缓存), reload 拿到的是 ready 态。
- 瞬态弹层/指示器在 ready 稳态会隐藏, 截图脚本要"连接即轮询、出现即交互", 不要先
  `waitForLoadState` 再慢慢找 (会错过窗口)。
- 想要"复现一次扫描"而不冷重启, 唯一途径是触发一次真正 rescan (manual refresh /
  改 projectDir / watcher 事件), 单纯 reload 无效。
- 关联既有 verify 摩擦: [[20260603-4.0-verify-macos-dev-agent-screenshot]]、
  [[20260604-4.0-verify-windows-click-stale-window-handle]]。
