# 工程摩擦记录

## 发生阶段

GH-155 4.0-verify (双轴评审 + e2e 抓到两个全绿测试下存活的正确性 bug)。

## 现象

同一根因两次现形: **test double 违反生产不变量, 让其守护的路径形同虚设**。

1. W2 graft 单测的 fixture 给同一文件的 shallow 行与 deep 行用了**不同 id** ('p-shallow'/'p-deep'), 而生产不变量 (A7, 本任务自己写的) 是同文件 shallow/deep 行**共享同一确定式 id**。graft 的 id 撞车去重路径因此从未被测到 — 用过滤前 id 集合去重的 BLOCKER (根级资产全量扫后两头丢行) 在单测全绿下存活, 靠对抗评审 Standards 轴发现。
2. runtime 全部单测的 fake scanner `scanAll` 直接 resolve, **从不发 partial 流**; 生产 helper 恒发 cumulative partial。`applyPartial` 在 commit 前冲掉 graft 源 (deep 行) 的连锁 bug 因此在单测层不可见, 靠 e2e 真 scanner 链路先红暴露。

## 工程师介入动作

无人工介入 — 双轴评审子代理 + e2e 新断言抓住; 但两个 bug 都到 verify 阶段才现形, implement 阶段的"目标测试绿即提交"节奏被回写打断两轮。

## 应沉淀的上下文或规则

**fixture/fake 的形状必须与生产不变量对齐, 否则测试守护的是一个不存在的系统**:
- 造 fixture 前先问: 这个实体在生产里有哪些**同一性不变量** (确定式 id / sourceKey 归一 / 同文件多行共键)? fixture 违反它 = 该不变量参与的所有分支 (去重/替换/撞车) 全部失真。
- fake 协作者要复刻**流形状**, 不只复刻终值: scanner 有 partial 流、IPC 有 push+invoke 双通道、watcher 有事件序列 — fake 只给终值时, 所有"中间态覆盖终态"类 bug (本仓已有 20260609 static-green 前科) 在单测层免疫。
- 自查锚点: 写 fake 时对照真实现签名里的**回调参数** (onPartial/onProgress) — fake 若从不调用某回调, 显式写一个"会调用它"的变体测试。
