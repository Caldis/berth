## 发生阶段

GH-109 (手写控件迁 HeroUI) 的 1.0-explore 审计与 4.0-verify 全量门禁。

## 现象

1. **断言原生 DOM 结构/角色的测试在控件换底层后必然破, 且单测文件单跑不暴露。**
   - 把 usage cost-mode `<select>` 迁到 HeroUI `Select` 后, `sessions-pages.test.tsx` 两个用例失败:
     `getByRole('combobox', { name: 'Cost mode' })` + `toHaveValue('auto')` + `fireEvent.change(el, { target:{value} })`
     全部基于原生 select 语义; HeroUI Select 是 `button[aria-haspopup=listbox]` + portal listbox, role 不是 combobox、无 value 属性、不响应 change。
   - 把 memory 状态徽标迁到 `Chip` 后, `memory-view.test.tsx` 的 `expectImportanceBadge` 失败:
     它按 `element.getAttribute('title') === title` 找文本元素, 但 Chip 把 `title` 放在根、文本在内层 content span。
   - 关键: 这些失败**只在 `pnpm test` 全量跑时出现** —— 我逐项迁移时跑的是各控件所在文件的单测 (top-nav/memory/hooks/capabilities 都绿), 而断言被打破的测试在**另一个文件** (sessions-pages 测 usage 页)。

2. **explore 用 grep 子串标 blast radius 会假阳性。**
   - `grep "ScopeSelect"` 命中了 `AppScopeSelection`/`setScopeSelection`/`scopeLabelForSelection`, 把 filter-bar 误判为"3 处消费、高 blast radius"; 实际只有 capabilities.tsx 真正用 `ScopeSelect`, `FilterBar` 组合组件全仓未引用 (死代码)。

## 工程师介入动作

- 全量 `pnpm test` 抓出跨文件回归后, 把受影响测试从"原生控件交互"改为"HeroUI 组件交互范式":
  原生 select: `getByRole('combobox')`+`fireEvent.change` → `fireEvent.click(getByRole('button',{name:/label/}))` + `fireEvent.click(await findByRole('option',{name}))`; value 断言改 `trigger.toHaveTextContent('Auto')`。
  Chip title: 改查 `element.closest('[title]')?.getAttribute('title')`。
- data-testid / aria-label / onFocus 等会经 HeroUI `filterDOMProps` 落到**内部 input**, 故 `getByTestId(..)`+`fireEvent.change` 仍可用 (已读 @heroui/input use-input.js 的 getInputProps 确认)。
- 审计改按符号边界 (import / JSX 用法) 确认消费方, 不信 grep 子串命中; 死代码按"只记录不删除"记入 docs/issues。

## 应沉淀的上下文或规则

- **迁 HeroUI 控件 = 跨文件测试影响**: 替换原生 `<select>`/`<input>`/`<details>` 或本地 pill 时, 必须 `pnpm test` **全量**回归, 不能只跑被改组件所在文件的单测 —— 断言被打破的测试常在消费该控件的**别的页面测试**里。
- **HeroUI 控件的测试交互范式**: 行为测试 (click trigger→click option / fireEvent.change on inner input via testid) 能跨迁移存活; 断言原生 role(`combobox`)、`value` 属性、或 DOM 层级(title 在文本元素自身)的测试会破, 需改为组件结构。
- **blast radius 用符号边界判定**: explore 标消费方/影响面时按 import 与 JSX 实际用法确认, grep 子串 (如 `ScopeSelect` ⊂ `AppScopeSelection`) 会虚高风险。

## 建议的流程改进

1. 1.0-explore 标 blast radius / 消费方时, grep 命中后用"是否 import / 是否 JSX 使用"二次确认, 排除子串假阳性。
2. 3.0-implement 迁移控件每步可跑该控件文件单测快速反馈, 但 4.0-verify **必须**全量 `pnpm test`; 不得以单文件绿替代。
3. 迁 HeroUI 控件前先在 design 列出该控件的测试驱动点 (combobox/change/value/title/testid), 预判需要同步更新的测试。
