# 工程摩擦记录

## 发生阶段

4.0-verify, GH-90 导航顶部栏真实 Electron 视觉验收。

## 现象

工作流要求 macOS UI 验收使用 Electron 主进程真实窗口坐标裁剪截图, 但执行
`pnpm dev:agent screenshot gh90-nav-verify --mode print-window --json` 返回
`dev:agent screenshot currently supports Windows only`。因此无法直接使用 `dev:agent screenshot`
完成 macOS 截图证据。

同轮继续排查时, `dev:agent start --id gh90-nav-verify --debug-port 9333` 能启动
agent-owned Electron 主进程, 但 `shouldRequestSingleInstanceLock(profile)` 仍返回 `true`。
已有用户 dev 窗口存在时, agent-owned 实例无法获得独立主窗口; CGWindow 列表中该 PID
只剩 `103x109` 的小窗口, 无法作为视觉验收截图目标。

## 工程师介入动作

- 先执行 `pnpm dev:agent guard before --id gh90-nav-verify --json`, 记录并保护用户已有 dev server。
- 使用 `pnpm dev:agent start --id gh90-nav-verify --debug-port 9333 --json` 启动 agent-owned 实例。
- 通过 CDP 控制 renderer 做页面切换和 DOM 验收。
- 截图改用 `osascript` 读取 agent-owned Electron 前台窗口 `{position, size}`, 再用 `screencapture -R` 裁剪到系统临时目录。
- 修正 `shouldRequestSingleInstanceLock(profile)` 为 agent profile 返回 `false`, 普通 dev 返回 `true`,
  并用 `tests/unit/dev-instance.test.ts` 覆盖。

## 应沉淀的上下文或规则

macOS 下 `dev:agent screenshot` 当前不能作为真实窗口截图工具。若 UI verify 需要截图,
必须保留 `dev:agent` 的进程所有权检查, 再用 macOS 系统窗口坐标和 `screencapture`
采集证据; 截图文件仍放系统临时目录, 不写入项目目录。

`--berth-agent-instance` 的目标是独立验证实例, 不能继续参与普通单实例锁。否则 workflow
要求的 agent-owned 真实窗口与主进程保护无法成立。

## 建议的流程改进

扩展 `scripts/agent-dev-core.mjs screenshot` 的 macOS 分支:

- 根据 agent-owned Electron 主进程定位可见窗口。
- 使用 AppleScript 获取窗口 position / size。
- 按显示器缩放比换算物理像素, 或调用系统截图 API 直接按窗口区域裁剪。
- 输出与 Windows 分支一致的 JSON, 包含 pid、窗口 bounds、输出路径和文件大小。

## 补充: 双实例同屏 + scaled 多屏下 osascript/screencapture 不可靠 (GH-107, 4.0-verify)

上面的 `osascript {position,size}` + `screencapture -R` 方案在以下环境失效:

- **窗口 z-order 命中错对象**: 用户 dev 与 agent-owned 是两个 Electron 窗口同屏重叠时, `set frontmost of <agent-pid>` 不保证把 agent 窗口提到最前; `screencapture -R <bounds>` 与 `System Events click at` 命中的是**当前前台**窗口, 会截到/点到用户 dev 窗口 (误触保护对象, 违反"不接管用户 dev")。本轮即因此一次截图落到用户 dev 的总览页, 且一次 close 点击坐标落在用户 dev 窗口上。
- **scaled 多屏坐标不等比**: scaled 显示器 ("more space" 或外接 4K "looks like 1920×1080") 下 osascript window points 与 renderer CSS px 不等比 (实测窗口 1489×984 points vs CDP innerW/H 1280×860, 比例 ≈1.16 且各轴不一致), `screencapture -R` 裁剪与点击坐标换算失真。
- 本机无 `cliclick`; System Events `click at` 在小目标 (28px close) 上易脱靶。

可靠替代 (本轮采用, 怎么做):

- **视觉证据优先 CDP `page.screenshot`**: `chromium.connectOverCDP('http://127.0.0.1:<debug-port>')` → `contexts()[0].pages()[0].screenshot({ path, clip })`。直接对 agent renderer 出图, 不受窗口 z-order / 多屏 / scale 影响, 可 `clip` 聚焦局部。缺点: 不含系统绘制层 (macOS 红绿灯), 那部分用 CDP 坐标数值佐证。
- **布局/位置验收用 CDP 运行时数值**: `el.getBoundingClientRect()` + `window.screenX/innerWidth/devicePixelRatio`, 比系统截图像素判断更精确 (本轮据此确认 drawer y=0 贴顶、backdrop y=40 护红绿灯、spacer 0-40、close y=56 避系统区)。
- **CDP locator 别按可见文本正则匹配**: `getByRole('button',{name:/raw/i})` 会命中标题里含该词的文本元素; 用 `textContent.trim()==='View Raw'` 精确匹配按钮。
- **真实 OS 命中点击** (draggable region / 系统非客户区) 只在 agent 窗口能独占前台且不与用户 dev 重叠时做 (移到无用户 dev 的副屏, 或单屏标定); 无法隔离时**不要盲 `click at`**。裁剪/点击坐标用"CDP 给目标元素染色 + 量截图像素反推", 不靠 `osascript size × dpr` 假设。
