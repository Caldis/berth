# 工程摩擦记录

## 发生阶段

GH-99 `harness-5.1-friction` 收敛后准备提交时。

## 现象

多个 Agent 共享同一个工作区, 即共享同一个 git **index (暂存区)**。我只 `git add` 了自己的文件, 但 `git diff --cached --name-only` 里出现了一个我从未碰过的文件 `docs/friction/_archive/20260604-5.0-archive-project-done-network-retry.md` —— 那是另一个 Agent 并发 `git add` 进共享 index 的。

若不察觉直接 `git commit`, 就会把他人并发暂存的文件一起提交, 违反"只暂存/提交自己改动"。这比"误用 `git add -A`"更隐蔽: 即使每次都显式按文件 `git add`, 暂存区仍可能被他人的并发 `git add` 被动污染。

附带的 `git add -p` 困境: 当同一文件 (如 `.agents/workflow/5.0-archive.md`) 同时含我的编辑和他人未提交编辑时, 无法只暂存我的 hunk —— 本工具不支持交互式 `git add -p`; 只能暂不提交该文件, 让我的编辑随下一个提交该文件的 Agent 一并 carry。

## 工程师介入动作

- 提交前完整核对 `git diff --cached --name-only`, 发现外来文件。
- `git restore --staged <foreign-path>` 把外来文件移出暂存区。
- 提交后立即 `git show --stat HEAD` 复核, 确认 commit 只含自己的文件。

## 应沉淀的上下文或规则

- **git index 跨并发 Agent 共享**: 别的 Agent 的 `git add` 会出现在你的 `git diff --cached`。"只 `git add` 自己的文件"不足以保证暂存集合干净。
- 提交前必须核对**完整** `git diff --cached --name-only` 是否只含本轮自己处理的文件 (不只假设自己的 add 是隔离的); 发现外来文件用 `git restore --staged <path>` 剔除。
- 提交后立即 `git show --stat HEAD` 复核 commit 实际内容只含自己的文件; 若混入他人文件, `git reset --soft HEAD~1` + `git restore --staged` 拆回, 不用 destructive reset。
- 同一文件含自己 + 他人未提交编辑且无法非交互拆分时, 暂不提交该文件, 让编辑随下一个提交该文件者 carry; 不强行整文件 `git add` 把他人未提交编辑带入。
