## 现象

用户指出首页总览会话列表还有明确 UX 问题: date 是 invalid, 路径没有按正确格式展示, token 和 price 都是 0。随后又指出 `/sessions` 页面也有类似共性问题。前一轮 Explore 虽记录了 invalid date 与 token/cost 为空的技术线索, 但没有在对用户的结论里把它们作为一组用户可见缺陷清楚列出; 路径格式问题与跨页面共性问题则遗漏了。

## 工程师介入动作

重新检查真实 `~/.claude/projects` 数据形态, 验证目录名是 `D--Code-berth` 这类编码路径, JSONL 行内存在真实 `cwd`; 同时验证存在 `ai-title.aiTitle` 与 `assistant.message.usage`。继续扫描 Overview、Sessions、Session Detail 三个入口, 确认它们共用 `SessionSummary` 的坏字段。已将这些 UX 问题补进当前任务的 `01-ANALYSIS.md` 验收标准。

## 应沉淀的上下文或规则

分析 UI bug 时不能只停在数据链路是否能跑通, 还要把用户实际可见字段逐项检查: 标题、日期、路径/项目、token、cost、模型、duration、空态、加载态。对列表类问题, 必须扫描所有消费同一数据契约的页面, 不只扫用户最先点名的页面。对 agent session 类数据, `.claude/projects` 目录名是索引用编码, 不是最终展示格式; 应优先用 JSONL 内的 `cwd` 等真实字段。

## 建议的流程改进

Explore 阶段增加一个“用户可见字段审计”小节, 对列表类 UI 至少列出每个列/行字段的来源、fallback、无效值表现和测试点。
