# 工程摩擦记录

> 关联: GH-111 (Codex×Claude 对抗审查); 用户 /goal "让 codex 对扫描引擎对抗审查"。

## 发生阶段
1.0-explore (用 codex exec 做对抗式代码审查)

## 现象
第一轮 `codex exec` 让 Codex 对整个扫描引擎做"覆盖+性能+可观测+其它"全维度对抗审查,
Codex 一边读 ~15 个引擎文件、一边联网查 Claude Code/Codex 官方目录规范, **耗尽模型上
下文窗口**: 输出 `ERROR: Codex ran out of room in the model's context window`, `-o`
最终消息文件未写, 整轮无产物。

## 工程师介入动作
重构分工后重跑即成功:
1. `--disable web_search` 禁掉 Codex 联网 (官方文档核验改由主 agent 用 WebSearch 做)。
2. 给**明确有限的文件清单** + 指示"grep/跳读, 不要逐字通读全部文件"。
3. 要求**严格简洁的编号输出** (一行式 `#N [维度][严重度][置信度] 标题—file:line—问题—建议`)。
4. 第二轮回灌用**紧凑摘要** (上一轮 finding + 我的裁决), 不让其重读全部文件。

## 应沉淀的上下文或规则
- **用 `codex exec` 审查大模块时, 默认 `--disable web_search`**; 外部产品/官方文档核验
  留给主 agent (Claude 有 WebSearch + 领域知识), Codex 专注代码层。两边分工而非都做全维度。
- 给 Codex **有限文件清单 + "跳读不全读" + 简洁输出格式**约束; 否则易在"读全部 + 联网"
  上烧光上下文。
- 多轮对抗时, 后续轮用**摘要回灌**, 不要求重读源文件。
- `codex exec -s read-only -o <file> - < prompt` 是干净的非交互审查范式 (read-only 沙箱 +
  最终消息落文件); 但 `-o` 仅在 Codex 正常完成时写, 耗尽上下文则无产物, 需从 stdout 兜底诊断。
- 关联多 agent 互操作既有记忆 [[20260219-multi-agent-cli-interop]]。

## 建议的流程改进
(由 harness-5.1-friction 消费) 在 `.agents/tools.md` 的 codex 用法补一条"大模块审查:
禁 web search + 限文件 + 简洁输出 + 摘要回灌; 官方核验归主 agent"的约定。
