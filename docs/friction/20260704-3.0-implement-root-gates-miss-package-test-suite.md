# 根级门禁不含 scan-engine 包内测试套件, 引擎改动本地全绿仍 CI 红

- action: 3.0-implement
- 日期: 2026-07-04
- 任务: GH-152 (T2 搜索判脏改造)

## 现象

GH-152 T2 重构 `engine/search.ts` 判脏机制后, 本地 `pnpm test` (根 vitest, tests/ 目录) + `pnpm harness:prepush` 全绿并推送; CI 三平台红 — 失败在 `pnpm --filter @berth/scan-engine test` 步骤的 `packages/berth-scan-engine/tests/search-signature.test.ts` (GH-145, 钉旧签名语义)。根级门禁与 CI 的测试面不一致: 包内套件 (17 文件 123 测试) 只有 CI 跑。

## 根因

`scripts/harness-prepush.mjs` 的 PREPUSH_TASKS 只有根级 `test`; CI workflow 另有独立的 `pnpm --filter @berth/scan-engine test` 步骤。GH-121 物理迁包时包内测试面与根级门禁产生盲区, 此前的引擎改动恰好没动到仅包内钉住的行为。

## 处理 (工具性根治, 非常驻规则)

- `harness-prepush.mjs` 增加 `test:scan-engine` 任务 (`pnpm --filter @berth/scan-engine test`), 与其余门禁并行 — prepush 测试面与 CI 对齐, 该摩擦类从机制上消灭。
- 受影响测试 (`search-signature.test.ts`) 已按 T2 新契约改写 (旧签名语义随机制一并废弃)。

## 教训

改 `packages/berth-scan-engine/src` 下任何行为, 目标测试可能钉在两处: 根 `tests/unit/` 与包 `packages/berth-scan-engine/tests/`。定位目标测试时两处都 grep; 门禁靠 prepush 对齐 CI 测试面兜底, 不靠记忆。
