# 工程摩擦记录

> task_id: GH-110 · 关联 Issue #110

## 发生阶段
3.0-implement (P3.1a: Scope global/user 切换改纯客户端过滤以实现秒级切换)。

## 现象
P3.1a 把 global/user 切换从"调 `projectScope.activate` 全量重扫"改为"纯客户端 `filterAssetsByAppScope`"。本地单测/renderer (switcher 7/7) 与 typecheck/lint 全绿, 据此推送。但 **windows-only 的 `tests/e2e/project-scope.e2e.ts` 在 CI 红**: 该 e2e 断言"切到 user 域后 `window.api.assets.search('e2e-skill')` 不再命中项目 skill"。纯前端过滤后, 服务端 `assets:search` 仍对全量快照检索 (作用域无关), user 域仍搜到项目 skill → 期望 false 实得 true。

根因双重:
1. **设计**: 作用域过滤只做在渲染层, 但 `assets:search` 是服务端 IPC、作用域无关 → 行为不一致。
2. **流程**: 因为本地全量 `pnpm test` (renderer) 偶发 flaky (usage-tooltip 超时, 见同期 issue), 我依赖 CI 作权威门禁推送, 但**没有在本地跑过该 e2e** (e2e 仅 windows CI 跑, 且需 `pnpm build` + electron, 较重), 于是 windows-only 的回归直到 CI 才暴露。

## 工程师介入动作
- 修复设计: runtime 持有 `scopeSelection` + 新 fast IPC `project-scope:set-scope` (无重扫, 秒级); switcher 每次切换通知引擎; `search` 按作用域过滤 (user 仅 user/enterprise; project/global 含全部, 因单 projectDir 快照即活动项目)。
- **本地 `pnpm build && pnpm exec playwright test tests/e2e/project-scope.e2e.ts` 验证通过**后再推送修复, 不再二次靠 CI 兜底。

## 应沉淀的上下文或规则
- **改动作用域 / 搜索 / 过滤 / IPC 读取语义时, 推送前必须本地跑相关 e2e** (尤其 `tests/e2e/project-scope.e2e.ts` 编码了"作用域影响 search"的契约); 不能只跑单测+renderer 就靠 CI 兜 windows-only e2e。
- 服务端读取 (search / health / sessions) 的作用域语义必须与渲染层显示过滤一致; 把作用域只放在渲染层会让服务端 IPC 行为漂移。
- 当本地全量 test 因已知 flaky 不可靠时, 对"行为变更"仍要定向跑会受影响的真实测试 (含 e2e), 而不是整体跳过靠 CI。

(由 harness-5.1-friction 消费)

- 评估把关键 e2e (project-scope) 纳入更轻量的本地可跑路径 (或在 PR 描述模板提示), 降低"只在 windows CI 暴露"的概率。
