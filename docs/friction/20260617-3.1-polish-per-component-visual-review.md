# 工程摩擦记录

> task: GH-138 首页模块化仪表盘 (3.1-polish, 用户两轮复审判定完成度 50%→65%, 远低于 Agent 自评)

## 发生阶段
3.1-polish (用户视觉复审打回, 指出大量未打磨细节)

## 现象
仪表盘有 9 个 widget × 多尺寸 (S/M/L/Wide/XL) × 多状态。Agent 用**整页截图**做视觉验收,
自评"高完成度"。但用户逐组件审视后发现一批整页截图看不出的问题:
- 多个组件 **M 和 L 尺寸肉眼无区别** (跨度相同, 内容也不随尺寸变)。
- 部分组件**缺 S 尺寸** (尺寸集不完整)。
- 部分组件**留白过大** (密度不足)。
两轮反馈完成度从 50% 到 65%, 均远低于 Agent 自评的 ~90%。根因: **没有对每个组件逐一做视觉验收**。

## 工程师介入动作
1. 建立逐组件验收清单 (04-POLISH R2-A): 每 widget 单独核验 ① 尺寸集完整性 (缺 S 补 S) ②
   M/L/S 各尺寸是否肉眼可分 ③ 留白/密度 ④ 美学 (排版/对齐/层级/色)。
2. 视觉验收改为 **CDP 逐组件截图** (聚焦单 widget + 切换其各尺寸), 不再只截整页。
3. 用子代理做逐组件设计评审, 返回简明 findings, 主 Agent 落地 (省主上下文)。

## 应沉淀的上下文或规则
- **多 widget / 组件库类前端任务: 视觉验收必须逐组件 × 逐尺寸 × 逐状态**, 不能用一张整页截图代替。
  整页截图会掩盖单组件的尺寸无区别、密度不足、留白过大、对齐瑕疵。
- **Design 阶段就为每个 widget 明确**: 支持哪些尺寸 (是否含 S)、各尺寸的内容密度差异如何拉开
  (条目数/字号/图形大小), 否则 M/L 必然长一样。尺寸预设 ≠ 仅改宽度跨度; 必须有可见的内容/密度差。
- **留白是密度决策**: 组件在其尺寸内应充分利用空间; 大面积空白 = 未打磨信号。
- 自评完成度对前端**不可靠**: 视觉/密度/美学是用户裁定项 (不变量 22 主观 taste), 必须逐组件请用户过目, 不靠 Agent 自判 "看起来不错"。
