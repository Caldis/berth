# 工程摩擦记录

## 发生阶段
4.0-verify (GH-114 agent-teams 运行时视图, 空态视觉验收)

## 现象
为截取页面空态, 经 CDP 在页面上下文执行 `window.api.teams.list = async () => ({teams: []})` 后来回切路由触发重取 — 页面仍渲染真实数据。contextIsolation 下 contextBridge 暴露的 `window.api` 在 isolated world 是不可变绑定, 页面侧重赋值**静默失败**, 无任何报错, 容易误判为"已 stub 但缓存没刷新"而浪费排查轮次。jsdom 测试里同样写法可行 (无 contextBridge), 加剧了误导。

## 工程师介入动作
无 (Agent 自查发现: 第二次截图仍是真实数据, 且复数修复经 HMR 生效证明页面确实 reload 过, 推断 stub 从未生效)。

## 应沉淀的上下文或规则
- **Electron 真机验收时, 不要用 CDP 改写 `window.api.*` 来构造数据态** — contextBridge 绑定在页面上下文不可重赋值且静默失败。jsdom 测试可以这么写, 真机不行。
- 构造"主进程数据为空/特定形态"的真机场景, 用**第二个 agent-owned 实例 + 环境覆写**: `HOME=$(mktemp -d) pnpm dev:agent start --id <id>-empty --debug-port <port>` (darwin 的 `os.homedir()` 读 $HOME); 验收后 `pnpm dev:agent stop <id>-empty`。本次空态截图即此法取得。
- 另一注意: locale/JSON 改动触发的 vite 热更新可能整页 reload, 会清掉先前 CDP 注入的任何页面态; 注入类操作要在无 pending HMR 时进行。

## 建议的流程改进
把上述两条并入 `.agents/workflow/4.0-verify.md` 的 CDP 验收要点 (或 berth-ui-visual-verify 备忘): "CDP 只读/交互, 不 stub contextBridge; 数据态用独立实例 + env 构造"。
