# 工程摩擦记录

> GH-124 T1 (2026-06-12)。

## 发生阶段
3.0-implement — `pnpm add/install` 新依赖 (electron-updater) 时。

## 现象
postinstall (`electron-builder install-app-deps`) 在 `node_modules/.pnpm/node_modules/@esbuild/aix-ppc64` 上 `ENOENT` 失败; 清掉一族后炸下一族 (`@radix-ui/number` — GH-105 已删依赖的残链)。`.pnpm/node_modules` (hoisted 虚拟目录) 内**系统性断链 junction** 累计 70 个 — 历史依赖删除/跨版本 pnpm 操作留下的目标不存在 junction; install-app-deps 遍历 stat 即炸。CI 干净 store 一直绿, 仅本机脏 store 触发。

## 工程师介入动作
- 逐族打地鼠两轮后改全量扫清: 遍历 `.pnpm/node_modules` (Depth 1), `LinkType 存在且 Target 不存在` 的条目 Remove — 一次清 70 个, postinstall 即 Done。
- 核实 root pnpm 为 9.15.4 (corepack 钉版正确, 非版本漂移问题; website 子目录曾观察到 10.32.1 是另一进程 PATH)。

## 应沉淀的上下文或规则
- 本机 `pnpm install/add` 在 postinstall 报 `.pnpm/node_modules/<scope>/<pkg>` ENOENT 时, **不要逐包清** — 直接全量扫清断链:
  `foreach ($e in (Get-ChildItem node_modules/.pnpm/node_modules -Recurse -Depth 1 -Force)) { if ($e.LinkType -and $e.Target -and -not (Test-Path $e.Target)) { Remove-Item $e.FullName -Force -Recurse } }`
- 断链仅影响 postinstall 的 install-app-deps 遍历; 日常 test/build/package (npmRebuild:false) 不受影响 — 所以它可以潜伏很久, 只在加依赖时炸。

## 建议的流程改进
(由 harness-5.1-friction 消费) BUILD_ENV 可补一行: 加依赖报 .pnpm ENOENT → 全量断链扫清一次。
