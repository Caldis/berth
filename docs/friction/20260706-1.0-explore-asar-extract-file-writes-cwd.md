# 工程摩擦记录

## 发生阶段
GH-157 explore, production `app.asar` 取证。

## 现象
使用 `pnpm dlx @electron/asar extract-file /Applications/Berth.app/Contents/Resources/app.asar out/main/index.js > /tmp/.../index.js` 时, CLI 没有把目标文件写到 stdout; 反而在当前工作目录生成/覆盖了相对路径目标名。结果误把仓库根的 `package.json` 覆盖成 asar 内的 production `package.json`, 并额外生成 `index.js`。

## 工程师介入动作
立即用 `git diff -- package.json` 确认该修改来自误操作, 执行 `git restore package.json` 并删除误生成的 `index.js`; 后续改用 `pnpm dlx @electron/asar extract <asar> /tmp/<dir>` 整包抽取到临时目录, 再读取目标文件。

## 应沉淀的上下文或规则
对 production asar 取证时, 不要在仓库根运行 `extract-file` 并假设其输出到 stdout。统一先创建 `/tmp/<incident>/asar` 目录, 用 `asar extract` 指定目标目录, 再从临时目录读取文件。所有 asar 取证产物必须放 `/tmp`, 不写项目目录。

## 建议的流程改进
若未来频繁需要取证 production Electron 包, 可在 harness 或 scripts 下提供只读脚本: 输入 app.asar 和文件列表, 强制输出到 `/tmp` 并拒绝目标目录位于仓库内。
