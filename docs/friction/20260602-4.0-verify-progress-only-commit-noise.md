> 可在正文交叉引用 task_id / issue, 不拆子目录。优化后移入 _archive/。

## 发生阶段

4.0-verify, task_id GH-33。

## 现象

执行过程中把 `INDEX.md` phase 更新、`03-PLAN.md` 勾选和测试证据这类进度状态文档单独提交并推送。用户认可及时 push 代码, 但指出如果只是工作进度相关文档变更, 可以等到有阶段性成果后再一起提交。

## 工程师介入动作

用户明确给出流程修正: “如果只是改动了工作进度相关的文档, 则先不用提交, 而是等到工作有阶段性成果后再推送”。

## 应沉淀的上下文或规则

应区分“阶段结果”与“进度状态”。需求分析、技术方案、实现代码、测试、归档属于阶段结果, 仍应通过对应检查后及时提交并推送。仅进度状态类文档, 例如 `INDEX.md` phase、`03-PLAN.md` 复选框和测试证据, 不需要单独形成 commit。

## 建议的流程改进

更新 harness 提交规则:

- 只改进度状态文档时, 暂不单独提交。
- 等下一次代码、测试、设计产物、归档或其他阶段结果一起提交并推送。
- 如果进度状态文档是当前阶段唯一剩余变更, 则在阶段结束、归档或停手前提交, 不把已验证状态长期留在工作区。
