## 应沉淀的上下文或规则
- **e2e 跑 `out/main` build 产物, 不是源码。** 改源码后用 e2e 判断改动影响前, 必须确保 out 是目标源码的 build: 要么 `pnpm build`, 要么确认 `dev --watch` 在跑且已 rebuild (看 out mtime); dev 退出后 out 即 stale, 之后的 e2e 反映旧 build。`playwright.config.ts` 无 globalSetup/webServer, 不会自动 build。
- **平台/CI 相关红, 先做 baseline 对比再归因。** `git status --short` 看清范围 → `git stash push -u -- <本次文件>` + `pnpm build` + 重跑, baseline 同样红 = 非本次引起; 不默认「测试红 = 我改坏了」, 也不靠读代码猜。共享工作区只 stash 自己的文件。
- **macOS 本地跑 unit/e2e = POSIX, 等同预演 Linux CI 的 `path.posix` 行为。** 前置开发在 Windows (ambient `path.win32`) 无法自检 POSIX; 在 macOS 复跑能提前暴露反斜杠字面量/路径解析类跨平台问题 (呼应 `20260607-3.0-implement-windows-backslash-path-literals-break-posix-ci`)。cap-0 测试沿用 parser-identity 既有「两侧同过 `dedupePathKey` 比较」模式, 故 macOS/CI 自洽绿。
