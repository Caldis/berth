## 现象
- 本地 Windows 全绿 (test 783 + build), 推送后 Linux CI `verify` 挂在 `tests/unit/scope-dedupe.test.ts`。
- 失败断言: 期望 relation 指向合并资产 id, 实得 `/home/runner/work/berth/berth/AGENTS.md` (原始路径回退)。
- 根因: 测试用 Windows 反斜杠路径字面量 `'D:\\Code\\react-zmage\\CLAUDE.md'`。POSIX `path.dirname` 把整串当**单一文件名** (无 `/`), dirname=`.`, `path.resolve('.', 'AGENTS.md')` → `cwd/AGENTS.md`, 与合并资产的 `D:\\...\\AGENTS.md` 路径不匹配 → relations 走兜底返回 resolvedPath 字符串而非主 id。
- 生产代码无此问题: 真实 OS 用原生分隔符, dirname/resolve 自洽; **仅测试字面量不可移植**。

## 工程师介入动作
- 测试内改用 `path.resolve(...)` + `path.join(dir, 'AGENTS.md' | 'CLAUDE.md')` 构建路径, 让 dirname/resolve 在 runner 本地 (POSIX 或 win32) 一致。
- 重新 push, CI 复跑。

## 应沉淀的上下文或规则
- **凡测试涉及 `path.dirname`/`path.resolve`/`path.join` 的跨文件路径解析 (relations、import-chain、归属、去重 key), 路径必须用 `path` 模块从一个 root 构建, 禁止硬编码 `D:\\...` 反斜杠字面量。** 字面量只在显式注入 `platform` 参数的纯函数测试 (如 `dedupePathKey(fp, 'win32')`) 中允许, 因为那类函数不依赖 ambient `path`。
- 本机 Windows 的 `pnpm test` 全绿**不代表** Linux CI 全绿: ambient `path` 在两平台是 `path.win32` vs `path.posix`, 反斜杠语义相反。路径解析类测试本地无法自检 POSIX 行为 → 写时即按可移植方式构造, 而非等 CI 暴露。
- 复用已存在的归一化真源: 物理路径归一用 `src/shared/asset-dedupe.ts` `dedupePathKey` (显式 platform 可测); 不要在测试里重写大小写折叠逻辑。
