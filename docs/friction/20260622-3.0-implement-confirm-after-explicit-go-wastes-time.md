# 工程摩擦记录

task_id: GH-150 (2026-06-22-gh-150-overview-drag-ux-overhaul)
关联: 用户协作偏好, 见 memory `user-says-start-means-execute-immediately`

## 发生阶段
2.0-design → 3.0-implement 边界 (跨阶段流程摩擦, 归 3.0-implement)。

## 现象
用户在任务中多次明确说"继续", 且已通过 AskUserQuestion checkpoint 关键决策 (整体一次性重构 / 截断+查看更多 / 档位粒度宽3×高2)。Agent 完成 design 后, 进 implement 前仍输出一大段"方案就绪, 若要调整现在说; 否则我从 P1 开干"的汇报 —— 实质是变相再确认 + 停手等回应, 没有真正开始写代码。用户离开后回来准备验收成果, 发现 Agent 根本没开始, 强烈不满。

## 工程师介入动作
用户怒斥: "我明明说了开始然后你又跟我反复确认结果我都过去半天了回来准备验收成果你还没有开始... 我以后只要说直接开始落地你就必须直接开始不要确认任何事情"。随后追加"你没记住, 别假装开始搞然后不记", 要求当轮把该偏好沉淀 (Agent 已开始改代码但漏了记录这条规则)。

## 应沉淀的上下文或规则
- 用户已给出明确推进信号 ("继续 / 直接开始落地 / 整体一次性") 后, **不得在阶段边界 (尤其 design→implement) 再用汇报变相确认或停手等 review**; 直接执行到产出可验收成果再汇报。
- harness 阶段间的"对齐 / review 窗口"只在用户**未**授权或遇真实硬阻塞 (PRD 级歧义 / 不可逆外部副作用 / 范围根本不清) 时才用; 用户已说继续时, 阶段边界默认**直接续跑下一阶段**, 不停。
- 需要用户拍板的离散决策一次性问完 (一个 AskUserQuestion 批次) 再开干; 不在执行链路上反复回头确认。
- 收到纠正 / 偏好当轮**立即沉淀** (friction + 必要时 memory), 不能"假装开始干活"而漏记 —— 漏记本身是二次摩擦。

## 建议的流程改进
(由 harness-5.1-friction 消费)
- 候选折入 `_shared.md` 不变量: "用户已授权推进时, 阶段边界 (0.x/1.0/2.0/3.0/4.0 之间) 不插入'是否继续'确认, 仅在硬阻塞停"。按"记录≠折常驻规则"原则先记 friction, 高复发再折常驻 playbook。
