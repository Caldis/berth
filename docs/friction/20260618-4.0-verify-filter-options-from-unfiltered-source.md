# 工程摩擦记录

> task: GH-138 全局 agent 筛选 (团队并行实现 + lead 集成验证)

## 发生阶段
4.0-verify (CDP 实测阶段, 静态门禁全绿后)

## 现象
全局 agent 切换器的**可选项**取自 `insights.agentSplit` —— 而 agentSplit 来自经 `agentView`
过滤后的 insights:dashboard。结果: 选中某个 agent 后, insights 以该 agent 重取, agentSplit 收缩
到只剩 1 项, 而切换器"≤1 agent 自动隐藏"逻辑触发 → **切换器自我消失, 无法切回**。
typecheck / lint / 全量 1216 测试全绿都没暴露 —— 因为渲染测试 mock 的 agentSplit 是固定数组,
不模拟"选择 → 重取 → 选项收缩"的动态往返。**CDP 真跑 (选 Codex → 切换器消失) 才暴露。**

## 工程师介入动作
切换器选项改为取**未经 agentView 过滤**的源: 从 store 全量快照 (`assets`) 按当前 project scope
(`assetMatchesAppScope`) 统计在场 agent, 不随 agentView 收缩。CDP 复测 All↔Codex 往返通过
(选中后切换器持久显示「Codex」, 菜单仍列全部 agent, 可切回 All)。

## 应沉淀的上下文或规则
- **筛选控件的"可选项"必须取自该筛选器作用域之外的数据源 (全集), 不能取自被它自己过滤后的结果。**
  否则筛选会反噬选项, 收敛到单值后控件自锁 (self-collapse), 用户无法回退。
  同类陷阱: 搜索建议列表不能只来自当前搜索结果; facet/分面过滤的可选 facet 值要从全集算;
  "按 X 分组"的 X 候选列表要独立于当前 X 选择。
- **判定数据源时先问: 这个列表会不会被它要控制的状态反向裁剪?** 会则必须换未过滤源。
- 数据驱动选项 (data-driven options) 默认要和"被驱动的过滤动作"解耦 —— 选项来自 ground set,
  过滤只作用于展示数据, 两条数据路径分开。

  范围选择器), Verify 必须 CDP 真跑**完整往返** (选中某项 → 再切回 / 切到第三项), 不接受仅静态

  set 来源, 与过滤数据路径分离。
