# 小步提交后需要及时推送

## 发生阶段

1.0-explore / GH-29

## 现象

用户明确指出: 提交都需要及时推送, 不要只停在本地。

当前 workflow 只强调“小步频繁提交”和提交前检查 staged 集合, 没有把 push 写成默认动作。长时间连续任务中, 如果只本地提交, 其他 Agent 或用户无法从远端看到最新状态。

## 工程师介入动作

- 更新 `.agents/workflow/_shared.md`, 将“提交后及时推送当前分支”加入最高优先级规则与不变量 11。
- 后续每个验证通过的小步提交后, 立即运行 `git push`。
- 如果远端拒绝或网络失败, 当轮说明原因, 后续优先处理远端同步。

## 应沉淀的上下文或规则

完成一个可独立验证的增量后:

1. 只暂存自己相关文件。
2. `git diff --cached` 核对 staged 集合。
3. commit。
4. `git push` 当前分支。

## 建议的流程改进

`harness-5.1-friction` 后续可检查是否需要给 commit policy 增加自动提醒, 例如在 archive 前检查 `@{u}..HEAD` 是否还有未推送提交。
