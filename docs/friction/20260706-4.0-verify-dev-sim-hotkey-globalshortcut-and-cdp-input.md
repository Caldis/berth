## 发生阶段

4.0-verify — 用 dev 模拟快捷键 (Ctrl/Cmd+Shift+U 重放 update:state 序列) 驱动 agent-owned 实例做视觉验收。

## 现象

三连坑, 共烧掉 ~5 轮排查:

1. **`globalShortcut` 与并行用户 dev 实例抢注**: OS 级全局快捷键 first-come-first-served; 用户自己的 `pnpm dev` (默认 Roaming profile, 先启动) 已持有注册, agent 实例注册**静默失败** (register 返回 false 无异常)。SendKeys 发出的键全部落进**用户实例**, 在用户正开着的窗口里重放假更新序列 (污染用户 UI, downloaded 是黏性终态会一直挂着)。
2. **改窗口级 `before-input-event` 后, CDP 注入键盘不触发它**: Playwright `page.keyboard.press` (CDP Input.dispatchKeyEvent) 的合成输入**不经过** Electron 的 PreHandleKeyboardEvent 管线 — 探针日志证实 attach 成功但 input 事件零触发。必须真实 OS 输入。
3. **真实 OS 输入需要前台焦点, 而 Windows 前台锁禁止后台进程 SetForegroundWindow**: 直接调用返回成功但焦点未切换。`SendKeys('%')` (Alt 技巧) 后再 SetForegroundWindow 可解, 并以 `GetForegroundWindow()` 回读断言真的切过去了再发键。
   附带: 组合键在 Chromium 是 `rawKeyDown` (无 char), handler 只匹配 `keyDown` 会漏; 需同时接 `keyDown || rawKeyDown`。

## 工程师介入动作

无 (Agent 自查自纠); 但用户实例被注入假更新状态属于本应避免的越界副作用 (靠后续 main 代码改动触发 --watch 重启才顺带清掉)。

## 应沉淀的上下文或规则

- dev-only 的键盘触发器**默认用窗口级 `before-input-event`, 不用 `globalShortcut`** — 全局快捷键在多实例 (用户 dev + agent verify) 场景必然抢注互踩, 且劫持整个系统的该组合键。匹配时接 `keyDown || rawKeyDown`。
- 验收要驱动"只有真实 OS 输入才能触发"的路径 (before-input-event / 非客户区命中等) 时: **先 `Get-CimInstance` 确认无用户 dev 或确认目标窗口属于本轮 agent 实例**, 再走 Alt 技巧 + `SetForegroundWindow` + `GetForegroundWindow` 断言 + SendKeys; CDP `keyboard.press` 对这类主进程输入钩子无效, 不要拿它当等价驱动。
- 反向可用: CDP 注入输入**会**走页面 DOM 事件 (renderer 级 hover/click/keydown 都可靠), 只是不进主进程 PreHandle 管线 — 两层驱动手段按目标层选择。
