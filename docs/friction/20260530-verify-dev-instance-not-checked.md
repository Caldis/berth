# 工程摩擦记录

## 发生阶段
verify (启动 app 做视觉验收时)。

## 现象
用户指出: Agent 在开发-测试闭环中没有检查当前是否已有运行的 dev 进程, 就直接 `pnpm dev` 启动新实例,
累计留下 4 个 electron-vite 实例同时运行, 端口从 5173 漂到 5175, 屏幕上出现两个 Berth 窗口。

## 工程师介入动作
用户截图指出多实例问题。Agent `pkill -9` 清理全部 berth electron-vite/electron 残留后, 改为单实例。

## 应沉淀的上下文或规则
1. 启动 app 前必须先 `pgrep` 检查是否已有运行实例; 有则复用 (vite HMR 已热更新到新代码), 直接截图, 不重启。
2. 仅在无实例或需冷启动验证主进程改动时才 pkill + 重启, 且重启前后都确认实例数。
3. 这是 [[verify-dev-zombie-port-drift]] 的根因前置: 不是"清理僵尸", 而是"启动前先查、能复用就复用"。

## 建议的流程改进 (已落地)
.agents/workflow/verify.md 步骤 3: 改为"启动前必须先检查运行实例, 已有则复用窗口直接截图, 不重复启动"。
