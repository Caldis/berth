## 发生阶段

verify

## 现象

Windows verify 阶段需要对 Electron 页面做视觉验收时, 临时 Win32 窗口枚举脚本先把 `$pid` 当作普通变量使用, PowerShell 报错提示该变量为只读或常量变量。改名后能枚举到 Berth 窗口句柄与坐标, 但 `CopyFromScreen` 截图仍截到前台遮挡窗口, 不能稳定证明目标 renderer 状态。

## 工程师介入动作

把脚本变量改成 `$windowProcessId` 这类普通变量后确认窗口枚举可用。随后放弃依赖屏幕坐标截图, 改用 Playwright Electron 启动构建后的 `out/main/index.js`, 并传入独立 `--berth-agent-instance` 避开现有开发实例, 直接断言 Usage 时间范围按钮状态并保存 renderer 截图。

## 应沉淀的上下文或规则

PowerShell 中 `$PID` 是内置只读自动变量, Windows 验证脚本不要用 `$pid` 作为 out/ref 临时变量名。Electron 页面验收优先使用 Playwright 直接控制 renderer; 只有需要验证真实桌面叠放、窗口边框或系统集成时, 才用 Win32/DWM 坐标截图。

## 建议的流程改进

在 `.agents/workflow/4.0-verify.md` 的 Windows UI 验收说明中补充:

- Win32 枚举窗口示例避免使用 `$pid` 变量名。
- 对 renderer 状态、按钮选中态、页面截图的验收, 优先使用 Playwright Electron 和独立 `--berth-agent-instance`。
- `CopyFromScreen` 截图需要先确认目标窗口置前且无遮挡; 否则只适合作为辅助证据。
