# 工程摩擦记录

## 发生阶段

4.0-verify, task_id: GH-10

## 现象

Windows Electron 视觉验收需要用真实窗口句柄截图。用 PowerShell 7 临时编译 C# helper 时, `System.Drawing` / `System.Drawing.Primitives` / `System.Private.Windows.Core` 引用缺失, `Bitmap` 和 `Graphics.CopyFromScreen` 编译失败。

随后改用 Windows PowerShell 5.1 仍需要在 `Add-Type -TypeDefinition` 时显式传入 `-ReferencedAssemblies @('System.Drawing.dll')`, 否则 `System.Drawing.Imaging` 也无法解析。

## 工程师介入动作

改用 `powershell.exe -NoProfile -EncodedCommand ...` 执行 Win32/DWM 截图 helper, 并在 `Add-Type` 中显式引用 `System.Drawing.dll`。窗口被其他应用遮挡时, `CopyFromScreen` 会截到遮挡内容, 因此最后用同一真实窗口句柄的 `PrintWindow` 生成验收截图。

## 应沉淀的上下文或规则

Windows verify 临时截图 helper 不应默认依赖 PowerShell 7 的 `System.Drawing` 编译环境。需要临时 C# + `System.Drawing` 时, 优先用 Windows PowerShell 5.1, 并显式传入 `System.Drawing.dll`。

如果需要证明 renderer hover / tooltip 状态, `CopyFromScreen` 只能在目标窗口确认置前且无遮挡时使用。存在遮挡时, 用真实 Electron 主进程窗口句柄 + DWM bounds + `PrintWindow` 作为截图证据。

## 建议的流程改进

把 Windows 截图 helper 固化为脚本或 dev:agent 子命令, 内置:

- 通过 `--berth-agent-instance` 查找 Electron 主进程窗口。
- 用 DWM bounds 记录真实物理窗口边界。
- 提供 `PrintWindow` 模式和无遮挡 `CopyFromScreen` 模式。
- 在 PowerShell 7 / Windows PowerShell 5.1 之间选择可工作的运行时, 避免 verify 阶段重复手写 Add-Type。
