## 发生阶段
0.0-new — 建 work 前验证 gh project scope 可用性时。

## 现象
1. `gh project list --owner Caldis` 报 `missing required scopes [read:project]` (exit 1)；`gh auth status` 显示 token scopes 仅 `gist read:org repo workflow`（无 project/read:project）。我据此判定 "project scope MISSING → 任务 blocked"。
2. 但 `gh api graphql '{viewer{projectsV2{totalCount}}}'` **成功返回 totalCount=6 (exit 0)** —— token 对 Projects v2 的**真实访问能力存在**。`gh project` 子命令的失败是 gh CLI **客户端 scope-字符串硬校验**的假阴性，不代表 token 无权限。
3. 更严重的行为错误：我没有据"确定性 + 工作流已规定处理"直接执行规定动作，反而抛出一个 3 选项 `AskUserQuestion`，其中还包含 "不要 GitHub 跟踪 / 跳过 task-state" 这种**违反 harness 大件必走 task-state 规则**的选项 —— 把不需要用户决策、工作流已规定的事外包给用户。用户判定为 P0 检测失败 + 愚蠢提问。

## 工程师介入动作
用户指出 "gh auth status 是有状态的，但你没有检测到" 并要求作为严重事故记录、修正行为。复核后用 `gh api graphql` 证实真实能力可用，确认 `gh project` CLI scope-gate 为假阴性。

## 根因
1. **探测器假阴性**：`gh project *` 子命令做客户端 scope-字符串断言；token 的 effective 能力（GraphQL 可读 `projectsV2`）与该 CLI gate 不一致。`scripts/harness-projects.mjs` 全程用 `gh project list/item-list/field-list/item-create` 子命令（line 460 等），因此每次都会撞这个 gate。
2. **没复用既有 friction**：[[20260620-0.0-new-macos-no-timeout-command-false-scope-failure]] 已明确 "scope 探测报失败先排除探测器本身问题再判真失效 / 上次已跑通的 gh project 能力这次报失败优先怀疑探测方式"。我把 `gh project list` 退出码当 ground truth，未用 GraphQL 探真实能力。
3. **把确定性情形升级成多选问题**：0.0-new step 8 已规定 "缺 scope → 提示固定 refresh 命令 + 置 blocked/pending-auth"。这是确定性动作，不是用户决策点。我却用 AskUserQuestion 外包，且提供了违反 harness 的选项。违背 AskUserQuestion 的使用边界（仅用于无法从请求/代码/工作流/默认值解决的真实用户决策）。

## 应沉淀的上下文或规则
- **gh project scope 探测以真实能力为准，不以 `gh project list` 退出码为准**：用 `gh api graphql '{viewer{projectsV2{totalCount}}}'` 探测；GraphQL 成功即 token 有 project 访问能力，`gh project` 子命令仍失败是 CLI scope-gate 问题（需 refresh scope 让子命令通过其断言，或改走 GraphQL），**不是无权限、不触发 pending-auth/STOP**。
- **工作流已规定处理方式的确定性情形，直接执行规定动作**（给固定 refresh 命令 / 置 blocked），**不升级成 AskUserQuestion**；**永不在选项里提供违反 harness 的路径**（如"跳过 task-state / 不要 GitHub 跟踪"）。AskUserQuestion 仅用于无法从请求/代码/工作流/默认值解决的真实用户决策。
- 复用 [[20260620-0.0-new-macos-no-timeout-command-false-scope-failure]]：能力/scope 探测报失败，先排除探测器（wrapper / CLI gate）假阴性，再判真失效；上次会话已跑通的 gh project 能力这次报失败，优先怀疑探测方式。
