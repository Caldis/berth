## 现象

两个叠加问题导致在 prepush 红灯时误 commit:

1. **管道 + 后台双重掩盖退出码**: 用 `pnpm harness:prepush 2>&1 | tail -25` 且 `run_in_background`。完成的 task-notification 报 `exit code 0`, 据此 (未 Read 输出文件) 直接 `git commit`。实际 prepush `exit 1`: `| tail` 把 pnpm 的非零退出码替换成 tail 的 0, 后台 wrapper 记录的就是这个 0。等于在 prepush 失败时提交了代码。
2. **高并发负载下 5s testTimeout flaky 超时**: prepush 内部并行跑 lint+typecheck+test, 叠加同机其他 agent 负载, collect 累计约 895s。三个重渲染测试 (`hooks-lifecycle-view` / `sessions-pages` / `usage-tooltip-label`) 报 `Test timed out in 5000ms`, 全是本任务**未触碰**的页面。单独低负载重跑这 3 文件 55 passed (1.4-1.8s), 证实是负载导致的 flaky, 非真红。

## 应沉淀的上下文或规则

- **gating 命令 (prepush/test/typecheck/lint/ci:wait) 在 run_in_background 时禁止接 `| tail` / `| head`**: 管道把上游退出码替换成管道末端的, task-notification 报的 exit 因此失真。要截断输出就重定向到文件 (`> out 2>&1`) 后台跑, 完成后 Read 该文件。这是 archived `20260604-4.0-verify-pipe-masks-exit-code` 在"后台 + 据通知 exit 直接 commit"的新场景延伸。
- **commit/push 前的门禁结果, 以输出内容 (passed/failed 字样) 判定, 不以退出码或 task-notification exit 判定**: 退出码可被管道 / wrapper 掩盖, 输出文本不会。
- **多 agent 并发 + prepush 内部并行下, 5s testTimeout 会让重渲染测试 flaky 超时**: 判定真红前, 单独低负载重跑失败文件; 单跑绿即 flaky, 不当真红。反向纪律同样重要 — 不能因"可能 flaky"在未确认前就 commit (本次顺序颠倒, 应先确认绿再 commit)。延续 `20260603-4.0-verify-harness-wall-time` 的负载维度。
