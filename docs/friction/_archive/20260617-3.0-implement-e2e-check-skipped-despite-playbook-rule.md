## 应沉淀的上下文或规则
- **技术规则已存在 (playbook line 30), 根因是"未消费"**: 大体量多阶段重构按 phase 快速推进时,
  每次 renderer push 前没回看 3.0-implement 的 DOM-change 检查项, 凭"unit 全绿"就推。
- **renderer DOM 结构改动 (尤其整页/布局/chrome 重写) 推送前是硬前置**: 先 `grep -rn "getByTestId\|getByRole\|getByText" tests/e2e/` 找该页面断言面 + 本地 `pnpm build && npx playwright test <受影响>.e2e.ts`; 不靠记忆、不靠 CI 兜底。门禁集 typecheck/lint/unit 永远不覆盖 e2e DOM 断言。
- **认知锚**: 规则写进 playbook ≠ 会被执行。体量越大、phase 越多, 越要在每个 renderer push 节点
  主动回看 playbook 的对应检查项 (与 [[runtime-behavior-needs-real-run]] 同源: 静态/部分平台绿
  证明不了全平台运行态)。
