# 工程摩擦记录

## 发生阶段

4.0-verify, task_id=GH-29。

## 现象

Settings manifest UI 验收需要用 Playwright 打开 renderer dev server 并截图。当前机器没有 Playwright 管理的 Chromium:

`Executable doesn't exist at C:\Users\mail\AppData\Local\ms-playwright\chromium_headless_shell-1223\chrome-headless-shell-win64\chrome-headless-shell.exe`

如果按 Playwright 提示运行 `playwright install`, 会引入额外下载和环境变化, 不适合作为普通 verify 的默认动作。

## 工程师介入动作

先检测本机浏览器路径, 找到:

- `C:\Program Files\Google\Chrome\Application\chrome.exe`
- `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`

随后用 `@playwright/test` 的 `chromium.launch({ executablePath })` 指向系统 Chrome, 完成 renderer 交互和截图。

## 应沉淀的上下文或规则

renderer 辅助截图不必强依赖 Playwright 管理浏览器。若本机已有 Chrome / Edge, 可以显式传 `executablePath`, 避免 verify 阶段临时下载浏览器。

这个替代路径只适用于 renderer 状态、弹窗、展开态、按钮选中态这类页面行为。涉及真实 Electron 窗口边框、标题栏、拖拽区或系统命中时, 仍应按 Windows Electron 截图规则使用真实窗口句柄。

## 建议的流程改进

把系统 Chrome / Edge fallback 固化到 verify 脚本或 helper 中:

- 先尝试 Playwright 管理浏览器。
- 缺失时探测常见 Chrome / Edge 路径。
- 把实际使用的浏览器路径写入验证证据。
