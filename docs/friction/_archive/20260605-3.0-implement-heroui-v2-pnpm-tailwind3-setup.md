## 发生阶段

GH-105 `harness-3.0-implement` 引入 HeroUI v2 (Tailwind 3.4 + pnpm 9 + electron-vite + React 19)。

## 现象

1. **`@latest` 是 v3 (Tailwind 4)**: `npm view @heroui/react dist-tags` → `latest: 3.1.0`。v3 强制 Tailwind v4 + CSS-first (`@import "@heroui/styles"`)、无 `heroui()` 插件、无 HeroUIProvider。berth 在 Tailwind 3.4, 必须**显式钉 v2** (`@heroui/react@2.8.10`), 不能用 `@latest`。
2. **peer 警告但实际可用**: `@heroui/theme@2.4.26` 声明 `peer tailwindcss>=4.0.0` (unmet, 实为 3.4.19)。但 `heroui()` 插件用的是 Tailwind 3/4 都稳定的 plugin API (`addBase` 注入 CSS 变量 + `addUtilities`), **在 TW3 实测正常**: build 后 CSS 含 115 个 `--heroui-*` 变量 + `bg-content1` 工具类 + `--heroui-primary: 212 100% 47%`。peer 警告 ≠ 不可用。
3. **pnpm 下组件静默无样式的坑**: HeroUI 的 Tailwind 插件靠 content glob 扫 `node_modules/@heroui/theme/dist/**` 生成 class。pnpm 把 `@heroui/theme` 藏在 `.pnpm/` 内, 顶层 `node_modules/@heroui/theme` 默认不存在; 且 `import { heroui } from '@heroui/theme'` 在 tailwind.config 里**无法解析** (只有 `@heroui/react` 顶层 symlink)。
4. **`public-hoist-pattern` 会强制 node_modules 全量重建**: 改 `.npmrc` 加 `public-hoist-pattern[]=*@heroui*` 后, 任何 pnpm 命令报 `ERR_PNPM_PUBLIC_HOIST_PATTERN_DIFF`, 必须 `pnpm install` 整体重建 — 在共享工作区 (别的 agent 可能在跑 `pnpm dev`) 是高 blast-radius 操作。

## 工程师介入动作

- 钉 `@heroui/react@2.8.10` + `framer-motion` (peer)。
- **把 `@heroui/theme@2.4.26` 加为直接 devDep** (`pnpm add -D @heroui/theme@2.4.26`): 直接依赖在 pnpm 下有顶层 `node_modules/@heroui/theme` symlink → 既让 `import { heroui } from '@heroui/theme'` 可解析 (不把 React 拉进 tailwind 配置), 又让 content glob `./node_modules/@heroui/theme/dist/**` 命中, **且不触发 `public-hoist-pattern` 全量重建**。删掉试过的 `.npmrc` hoist 方案。
- tailwind.config: `plugins:[tailwindAnimate, heroui()]` + content 加 theme dist glob, 保留 `darkMode:'class'`。
- 用 build 产物 grep `--heroui-*` / `bg-content1` 作为"TW3 下有样式"的 gate 证据 (P1 烟测), 不靠猜。

## 应沉淀的上下文或规则

- 本仓库 (Tailwind 3.4) 集成 HeroUI **只用 v2 线** (`@heroui/react@2.8.x` + `@heroui/theme` 作直接 devDep)。升级 HeroUI 前先确认是否要先迁 Tailwind v4 (v3 才是 HeroUI 的未来线)。
- 共享工作区下避免改 `public-hoist-pattern` (强制重建); 优先"把插件包加为直接依赖"获得顶层 symlink。
- **附带测试陷阱 (React Aria 浮层焦点)**: jsdom 下 `fireEvent.click(button)` 不会让按钮获得焦点 (真实浏览器会)。HeroUI Modal/Popover 的"关闭后焦点归还 trigger"靠 React Aria 在打开时捕获 `document.activeElement` → 测试里若只 click trigger, 捕获到的是 body, 归还断言失败。修复: 测试中先 `trigger.focus()` 再打开。断言层面测**结果** (打开/关闭/Escape/焦点归还), 不测库内部 Tab 循环顺序。

- **⚠ prepush 不含 e2e — HeroUI 浮层改动必须本地补跑 e2e**: `pnpm harness:prepush` 只跑 lint+typecheck+vitest, **不跑 `pnpm test:e2e` (Playwright+Electron)**。HeroUI Modal/Dropdown 迁移引入了 vitest+jsdom **抓不到、CI Windows e2e 才暴露**的两类失败 (GH-105 P5.1 settings dialog 推后 CI 红灯):
  1. **React Aria dialog 可访问名污染**: dialog 的 `aria-labelledby` 指向整个 ModalHeader, 把放进 header 的 close 按钮 (aria-label "关闭") 一并算进名字 → dialog accessible name 变 `"设置 关闭"`, e2e `getByRole('dialog',{name:/^设置$/})` 失配。**jsdom 的 accname 算法比真实 Chromium 宽松, vitest 单测能过、Playwright/Electron 才失败**。修复: ModalHeader **只放标题**, close 按钮渲染在 ModalHeader **之外** (ModalContent 直接子节点, 绝对定位)。
  2. **跨测试焦点竞态**: 上一个 e2e 关闭 HeroUI Modal 后, React Aria 的 restoreFocus 异步执行; 若测试 Escape 后不 `await expect(dialog).toBeHidden()` 就结束, 残留的 restoreFocus 会偷走下一个测试 (如 Ctrl+K 搜索框) 的焦点 → 间歇 flaky。修复: 浮层 e2e 用例 Escape 后必须 await 关闭完成, 做干净 teardown。
  - **规则**: 改动任何 HeroUI/React-Aria 浮层 (Modal/Drawer/Dropdown/Popover/Tooltip) 后, 推送前**本地跑 `pnpm exec playwright test app.e2e.ts`** (注意 pnpm `--` 吞参, 用 `pnpm exec playwright test --grep "..."` 而非 `pnpm test:e2e -- -g`), 不能只靠 prepush。
