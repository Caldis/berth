# 工程摩擦记录

> GH-121 B2 (2026-06-12)。

## 发生阶段
3.0-implement — main 消费面 18 行 import 改写。

## 现象
对 7 个文件用 PowerShell `-replace` 带 scriptblock 回调 + 多分支捕获组做"重组式"批量改写, 部分行分组不匹配抛 "Cannot index into a null array", 部分行被**静默写坏** (说明符丢段 `@berth/scan-engine/assets/...`、截断 `from '@berth/scan-engine/`); 另有文件被用户 dev 进程瞬时锁定 Set-Content 失败, 三种结果混在一起需逐文件重盘。

## 工程师介入动作
- 停止批量, 逐文件 Read + Edit 修复 7 个文件全部 import 行。
- 后续 tests 批量改写改用**无分组重组的纯前缀替换** (`from '(\.\./)+src/main/engine/` → 固定字符串), 39 文件一次成功零损坏。

## 应沉淀的上下文或规则
- 批量改写纪律按"替换形态"分级: **纯前缀/整串替换** (无捕获组参与重组) 可批量; **需要分组重组/条件分支**的改写一律逐文件 Edit — 文件数少 (≤10) 时逐文件本来就更快更可审。
- scriptblock `-replace` 失败不是原子的: 部分行改坏 + 部分文件锁定跳过会留下混合状态, 批量后必须立刻 grep 验证"目标模式残留=0 且新说明符无畸形" (如 `scan-engine/$`、`scan-engine/'`) 再继续。
