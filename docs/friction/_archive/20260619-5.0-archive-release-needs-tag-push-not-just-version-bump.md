# 工程摩擦记录

task_id: GH-141 (发版 0.4.2 — release tag 缺失)

## 发生阶段
5.0-archive 之后的"发版"。0.4.1 / 0.4.2 已声称发版, 用户端 (electron-updater) 实际仍停在 0.4.0。

## 现象
"发版" 被等同于 `chore(release): bump version` 改 package.json + commit + push master 就宣称完成。但本项目真实发布链路:
- `release.yml` 触发条件**仅** `on: push: tags: 'v*'`。
- 推 `vX.Y.Z` tag 才会跑多平台构建 + mac 签名公证 + `gh release create` + 上传 `latest*.yml` (electron-updater 自动更新数据源)。
- 改 package.json version + commit **不触发任何发布**, 也不自动打 tag (无 `postversion` 钩子、无 release 脚本、无发布文档)。

结果: 0.4.1 / 0.4.2 的 bump commit 进了 master, 但 `git tag` 停在 v0.4.0, GitHub Release 最新仍是 Berth 0.4.0, `latest-mac.yml` 指向 0.4.0 → 用户端 app 自动更新查到的最新版就是 0.4.0。"发版没发"。

## 工程师介入动作
- `git tag -a vX.Y.Z <package.json 版本一致的 commit> && git push origin vX.Y.Z` 触发 release.yml。
- 监听 release run 跑完 (多平台 build + 公证, 上次 v0.4.0 耗时 ~10min)。
- `gh release view vX.Y.Z` 回读确认目标版本 release 存在, 含全平台 assets + `latest*.yml`。

## 应沉淀的上下文或规则
- **"发版" 的完成定义 = GitHub Release 页面出现目标版本** (含全平台 assets + `latest*.yml`), 不是 package.json bump + commit。用户明确这是**验收硬项**。
- 唯一发布触发 = 推 `vX.Y.Z` annotated tag (匹配既有 v0.4.0 风格); tag 必须指向 package.json version 与之相等的 commit, 否则构建产物版本与 tag 错位、更新源错乱 (在 0.4.2 的 HEAD 上打 v0.4.1 即此坑)。
- 版本号可不连续: 未发布过的中间 patch (如 0.4.1) 可跳过, 直接发当前 HEAD 版本; release.yml changelog 取 `上一 tag..当前 tag` 区间, 被跳过版本的 commit 仍并入, 不丢内容。
- 宣称"发版完成"前必须 `gh release view vX.Y.Z` 回读成功; 只看到 tag 已推 / run 已触发就收手不算完成 (同 4.0-verify "CI 未出结论不得宣称通过" 教训, 同源根因: 把"触发"误当"完成")。

## 建议的流程改进
(由 harness-5.1-friction 消费)
- AGENTS.md 增 `# RELEASE` 段, 把上述验收硬项常驻 (本轮已同步落地)。
- 5.0-archive 若任务需发版: 在 "CI 绿 + 提测" 之外追加 "推 vX.Y.Z tag → 监听 release.yml → `gh release view` 回读目标版本" 三步, 缺一不算发版完成。
