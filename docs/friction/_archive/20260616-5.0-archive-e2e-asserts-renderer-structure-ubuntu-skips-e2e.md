## 应沉淀的上下文或规则
- **改 renderer DOM 结构 (移除/改 breadcrumb / heading / nav / sidebar / 页面 chrome) → 必须 grep `tests/e2e/` 对应的 role/testid/text/getByRole 断言并同步, 不能只改 unit 测**。e2e 用 Playwright role/text 定位, 与 unit 的 testing-library 查询是两套独立断言面, 改了组件结构两边都要跟。
- **ubuntu CI 不跑 Electron e2e (无 display)**: 本地 unit 绿 + ubuntu 绿 ≠ e2e 绿。e2e 闸门只有 macOS + windows。绝不能从 ubuntu 绿推断 e2e 健康。
- **声明 renderer-touching 任务"完成"前, 跑 `pnpm test:e2e` (或至少 grep tests/e2e 改动选择器)**。门禁集 typecheck/lint/unit 不覆盖 e2e DOM 断言。
- 共享工作区下本地 `pnpm build` 可能与他 agent 的 `electron-vite dev --watch` 抢 out/; 若无法安全本地跑 e2e, 退而求其次: grep e2e 断言面 + 靠 CI 失败信息逻辑推定 (如本次"element not found"已证 DOM 不存在), 再推送验证。
- harness:ci:baseline 是归档前的兜底闸门 — 它捕获了这次红。**归档必须先过 baseline, 不能跳。**
