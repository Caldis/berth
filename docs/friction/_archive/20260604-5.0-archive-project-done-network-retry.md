# 工程摩擦记录

## 发生阶段

5.0-archive, GH-101 空态统一任务收尾。

## 现象

archive 的 `node scripts/harness-projects.mjs done docs/works/{task}` 连续 3 次失败, GitHub GraphQL 分别报:

- `Post "https://api.github.com/graphql": unexpected EOF` (两次)
- `Post "https://api.github.com/graphql": net/http: TLS handshake timeout` (一次)

关键观察: 三次失败**断点字段各不相同** (一次在某 `--number` 字段, 一次在 `--date` Archived at 字段, 一次在 `--single-select-option-id` 字段)。说明 `done` 是顺序逐字段写入且**非幂等续传**: 每次调用都从头重写整组 Project 字段, 网络抖动下很难一口气跑完, 但每次又确实推进了一部分字段。这容易让人误判为"逻辑/授权错误"或"archive 被阻塞"。

## 工程师介入动作

- 先排除授权/逻辑因素: 错误是 `unexpected EOF` / `TLS handshake timeout`, 属 GitHub API 间歇性网络不可达, 非缺 scope、非字段非法。
- 不手动反复敲 (反复手敲本身是元摩擦)。改用**后台带退避的有界重试循环** (最多 12 次, 间隔 12s) 跑 `done`; 主 agent 不轮询, 等后台完成通知。
- 网络恢复后后台首次重试即成功: `... is Done`。
- 严守不变量: 确认远端回读 Done 后才 `git mv` 任务目录, 不在未 Done 时移动。

## 应沉淀的上下文或规则

- GitHub API 抖动期间, `harness-projects done` / `ensure` 这类多字段顺序写入命令易中途失败, 且断点漂移; 单次失败不等于 archive 阻塞, 也不等于命令有 bug。
- 正确处置 = 有界退避重试 (后台执行, 符合 "非本地门禁可由子代理/后台执行" 的约定), 主 agent 消费成功结果后再推进归档移动。
- 与既有 friction `20260603-4.0-verify-harness-wall-time.md` 区分: 那条讲门禁**整体慢** (Project 同步约 28s 等); 本条讲网络抖动下的**韧性/重试**, 是不同维度。

## 建议的流程改进

- `harness-projects done` / `ensure` 内置幂等续传: 写入前回读, 跳过已是目标值的字段; 每字段写入失败时带短退避重试, 避免整组从头重来。
- 或脚本暴露 `--retry N --backoff S` 选项, 把重试收敛进命令本身。
- workflow 文档在 archive / ensure 步骤注明: `unexpected EOF` / `TLS handshake timeout` 属可重试网络抖动, 用有界重试 (后台) 处理, 不手敲、不误判阻塞。

## 收敛去向 (5.1-friction)

已固化为规则:
- `.agents/tools.md` harness-projects 段: 新增 `done`/`ensure`/`fields ensure` 多字段顺序写入、非幂等续传、瞬时网络错误 (EOF/TLS timeout) 可重试且失败字段漂移、有界退避重试 (可后台)、回读确认 Done 才移目录。
- `.agents/workflow/5.0-archive.md` step 2: 在 Project done 步骤补充同义可重试网络错误处置规则。

未固化为规则 (留待独立任务): "让 `harness-projects.mjs done/ensure` 内置幂等续传 + 每字段退避重试 (或 `--retry/--backoff` 选项)" 属工具脚本改造, 不在 friction 收敛范围; 如需推进建议另立 `docs/issues/` 的 tooling-ci 改进项。
