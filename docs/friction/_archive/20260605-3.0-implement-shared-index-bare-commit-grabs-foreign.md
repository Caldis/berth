## 发生阶段

GH-100 记忆/指令页后续迭代 (instructions scope chips) 的小步提交。

## 现象

多个 Agent 共用**同一个 git 工作区和 index**。我只 `git add` 了自己的两个文件:

```bash
git add src/renderer/src/pages/instructions.tsx tests/renderer/instructions-guidance.test.tsx
git commit -F - <<'EOF' ... EOF
```

但 `git commit` (无 pathspec) 提交的是**整个 index**。此刻另一个 Agent 正在批量归档 friction, 已经把若干 `docs/friction/*.md → _archive/` 的 `git mv` 改名**预暂存**在共享 index 里。结果我的提交 `5d733e2` 把一个**别人的 friction 改名**一起带走了 (`git show --stat` 显示第 3 个文件), commit message 却只描述我的改动 → 误提交他人工作、attribution 错乱。

## 工程师介入动作

- 确认该提交未推送且仍是 HEAD (`git rev-parse HEAD origin/master` + `git branch -r --contains HEAD` 为空)。
- 按 invariant 11 用非破坏性方式纠正:
  ```bash
  git reset --soft HEAD~1                 # 拆回索引, 不动工作树
  git commit -F msg -- <my-file-1> <my-file-2>   # 显式 pathspec, 只提交自己的文件
  ```
- 重提后 `git diff --cached` 确认: 我的 commit 只含 2 个文件; 别人的 4 个 friction 改名仍**留在 index 里**, 交还给那个 Agent 自己提交, 我不 `restore --staged`、不碰。

## 应沉淀的上下文或规则

- **共享 index 下, 提交一律用显式 pathspec**: `git commit -F <msg> -- <file...>` (或 `git commit <file...>`), 不要 `git add <file>` 之后裸 `git commit`。裸 `git commit` 提交整个 index, 会把其他 Agent 在同一 index 里预暂存的改名/新增一并带走, 即使你只 `git add` 过自己的文件。
- `git diff --cached --name-status` 核对必须在**提交前**做; 但即便核对过, 在你 commit 前的瞬间别的 Agent 仍可能 stage 新文件, 所以 pathspec 提交才是根治 (核对是补充, 不是替代)。
- 误提交他人文件时, 只在**未推送且仍是 HEAD** 时用 `git reset --soft HEAD~1` + pathspec 重提; 已推送或已被压到历史中段则不可重写 (见 `20260604-4.0-verify-shared-branch-ci-red-foreign-commit`)。
