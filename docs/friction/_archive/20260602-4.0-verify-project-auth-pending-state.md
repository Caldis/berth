# Project 授权缺失时不能用占位 item_id

## 现象

GH-13 进入验证收尾时, `node scripts/harness-projects.mjs ensure docs/works/2026-06-02-gh-13-hook-operation-recovery-center` 因本机 `gh` 缺少 `project/read:project` scope 失败, 提示运行:

```bash
gh auth refresh -h github.com -s project,read:project
```

任务 `INDEX.md` 临时写了 `gh_project.item_id: TBD`。后续 `pnpm harness:check` 和 `node scripts/harness-projects.mjs check --strict` 没有拦住这个占位值, 让 active work 看起来已经绑定 Project, 但 archive 实际没有可用的 Project item id。

## 处理

- `harness-check` 要求 `gh_project.item_id` 必须是 `PVTI_...` 形式的 GitHub ProjectV2Item node id。
- `harness-projects check --strict` 同样拒绝 `TBD` 这类占位值。
- 缺少 Project 授权时只能使用 `phase: blocked` + `gh_project.status: pending-auth`, 不允许填假 `item_id`。

## 后续

授权恢复后运行 `node scripts/harness-projects.mjs ensure docs/works/{task}`, 由脚本回写真实 `PVTI_...` item id, 再继续 verify/archive。
