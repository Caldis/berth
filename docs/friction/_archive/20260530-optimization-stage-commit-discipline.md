# 工程摩擦记录

## 发生阶段
optimization

## 现象
harness 分发调整已经完成并通过验证, 但没有立即提交。工作区同时存在其他 agent 的应用改动和 harness 改动, 后续查看时会混在一起, 增加审查和回滚成本。

## 工程师介入动作
用户明确要求: 完成一个步骤或阶段后应尽可能提交。当前轮开始按“只暂存自有变更”的方式提交已完成的 Claude skills / commands 收敛改动, 不把其他工作区改动带入提交。

## 应沉淀的上下文或规则
harness 任务中, 一个可验证步骤或阶段完成并通过对应门禁后, 默认提交该阶段自有改动。若工作区已有其他人或其他任务的改动, 只暂存本阶段相关文件或相关 hunk, 并在最终说明中列出未纳入提交的脏工作区。

## 建议的流程改进
后续执行 `opsx-*` 阶段时, 把“验证通过 -> 精确暂存 -> 提交”作为阶段结束动作。跨阶段工作不要长期停留在未提交状态。
