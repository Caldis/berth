# 工程摩擦记录

## 发生阶段

3.0-implement

## 现象

workflow 入口只有动词名, 没有顺序编号, 用户需要靠上下文判断步骤位置。friction 和 docs/issues 会自动记录, 但 archive 后没有固定提醒用户哪些内容仍待清理。

## 工程师介入动作

补充有序 action id 设计, 增加 issues 收敛动作, 并要求 archive 报告列出本次产生或关联的 friction / issues。

## 应沉淀的上下文或规则

- workflow 动作使用 `{major}.{minor}-{verb}` 命名, 例如 `3.0-implement`。
- 可选动作使用关联步骤的子编号, 例如 `3.1-polish`。
- friction 命名中的阶段段改为 action id。
- archive 只提醒可选清理动作, 不自动执行 `5.1-friction` 或 `5.2-issues`。

## 建议的流程改进

由 `5.1-friction` 消费时, 检查 archive 提醒是否足够清楚, 以及 issues 收敛动作是否能减少 `docs/issues/` 长期堆积。
