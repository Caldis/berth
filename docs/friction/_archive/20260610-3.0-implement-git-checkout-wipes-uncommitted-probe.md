# 工程摩擦记录

> GH-115 T1 对账网自证步骤 (临时注入伪通道→确认红→撤销) 中, 用 `git checkout <file>` 撤销注入, 把同文件**未提交的重写**一并回滚, 被迫重写恢复。

## 发生阶段
3.0-implement (GH-115 T1)。

## 现象
preload/index.ts 处于"已重写未提交"状态; 为验证对账测试有效性注入一行伪通道后, 用 `git checkout src/preload/index.ts` 撤销注入 — checkout 回滚到 HEAD, 重写工作全部丢失。

## 工程师介入动作
无 (Agent 自查自复原, 内容尚在上下文), 损失一轮重写。

## 应沉淀的上下文或规则
- **对未提交文件做实验性注入时, 撤销只能用反向 Edit (删那一行), 禁止 `git checkout/restore <file>`** — 后者回滚的是整个文件到 HEAD, 不是"撤销最后一步"。
- 更稳的自证顺序: 先把真实改动提交 (或至少 `git add` 后用 `git diff` 区分), 再做注入实验; 实验态与工作态不共存于同一未提交文件。

## 建议的流程改进
- 涉及"临时改源码做验证再撤销"的步骤 (网自证/红绿验证), playbook 默认顺序: 真实改动先 commit → 注入 → 验证 → 反向 Edit 或 checkout (此时安全)。
