> 可在正文交叉引用 task_id / issue, 不拆子目录。优化后移入 _archive/。

## 发生阶段
4.0-verify / GH-68 推送后 CI 等待。

## 现象
`pnpm harness:ci:wait -- --sha 5b7c760 --timeout 600 --poll 5` 超时并报 `no CI run found for 5b7c760 on master`。

同一时间 `gh run list --branch master` 已显示 `fix(inspector): trap focus in raw drawer` 的 CI 成功, 完整 SHA 为 `5b7c7602a1bc50d8248c8bbf44baf599bee17246`。

## 工程师介入动作
改用完整 SHA 重新执行 `pnpm harness:ci:wait -- --sha 5b7c7602a1bc50d8248c8bbf44baf599bee17246`, 脚本成功匹配 `CI#26818215571`。

## 应沉淀的上下文或规则
CI wait 工具应接受 full SHA 和不歧义的 short SHA。否则人和工具都容易按 Git 常用短 SHA 传参, 导致误判 CI 未触发。

## 建议的流程改进
- 修复 `scripts/harness-ci-gate.mjs`: 先用 `git rev-parse <sha>` 将短 SHA 解析为完整 SHA, 再传给 `gh run list --commit`。
- `findWorkflowRunForSha` 对短 SHA 使用 `startsWith` 匹配, 保留 full SHA 精确匹配。
- 增加 harness 测试覆盖短 SHA。
