## 现象

用户要求“搜索功能上移至导航栏”时, Agent 将其理解为移除侧栏主搜索入口, 并在方案与实现中删除了 `Sidebar` 的全局搜索按钮。用户随后澄清: 需要上移的是页面内部搜索/筛选, 左侧导航栏搜索不要动。

同一任务中用户继续澄清: 顶部导航栏上的搜索应随页面切换改变。例如切换到 Memories 时, 右上角展示该页面的 “Search memories...”, 页面内容区搜索栏移除, 且快捷键触发页面搜索。

## 应沉淀的上下文或规则

当需求描述“页面内部搜索”“页面内搜索”“搜索上移到顶部导航”时, 必须明确区分:

- 侧栏全局搜索入口属于 app shell 导航能力, 未被点名时不得移除。
- 页面内容区内的 filter/search/input/scope 控件属于页面级 action, 可迁移到顶部导航。
- 顶部导航搜索不是全局搜索弹窗按钮; 有页面搜索时必须绑定该页面的 value/onChange/placeholder, 并随路由切换。
- `Ctrl/⌘K` 的优先级: 页面搜索存在时聚焦页面搜索, 页面搜索不存在时打开全局搜索。
- 设计文档应写明两者的边界, 测试需覆盖 app shell 搜索入口保留。

## 建议的流程改进

1. UI 迁移任务中, 将 app shell search 与 page-local search 分别列入验收项。
2. 涉及导航 shell 改动时, 为侧栏关键入口增加回归断言。
3. 页面搜索迁移时, 同时增加快捷键聚焦与内容区搜索栏移除的回归断言。
