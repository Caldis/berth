# 工程摩擦记录

> task: GH-113 (docs/works/2026-06-07-gh-113-scope-refactor-convergence/)

## 发生阶段
4.0-verify (真跑 observable 验证后清理 agent-owned 实例)。

## 现象
- `pnpm dev:agent stop verify-gh113` 在 Windows **首次报 `EPERM, Permission denied`**, 指向 `%TEMP%\berth-agent-dev\<id>` profile 目录, 退出码 1。
- 误以为实例没停。实查 `Get-CimInstance Win32_Process -Filter "Name='electron.exe'"` 过滤 `--berth-agent-instance=<id>` 已无主进程 → **electron 已被 kill, EPERM 只发生在随后删 profile 目录这一步** (electron 退出与文件锁释放之间有时序竞争, 立即 rmdir 撞锁)。
- 稍等 2s 重试 `stop` 返回 `{ "status": "missing" }` (进程与 state 已清), profile 目录也删除成功。

## 应沉淀的上下文或规则
- **Windows 上 `dev:agent stop` 首次 EPERM ≠ 没停**: 进程通常已 kill, 失败只在删 profile temp 目录。先用 `Get-CimInstance Win32_Process` 按 `--berth-agent-instance=<id>` 确认主进程已无, 再稍等重试 `stop` (或忽略 temp 残留, 它无害)。
- **禁止**因为 stop "失败" 就改用 `taskkill`/`Stop-Process` 批量清 — 会误杀用户 dev (verify 铁律)。targeted `dev:agent stop` 重试即可。

## 建议的流程改进
- `scripts/agent-dev-core.mjs` 的 stop 应容忍 profile 目录删除的 EPERM: 进程已 kill 即视为 stop 成功 (status=stopped), 把 rmdir 失败降级为 best-effort 清理 + warning, 不返回非 0。已记 issue (按需) `docs/issues/2026-06-09-IMPROVEMENT-devagent-stop-tolerate-profile-eperm`。
