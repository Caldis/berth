## 现象
- 本地 typecheck/lint/test 已跑绿, 据此提交推送; CI 却在 `pnpm lint` 红 (两平台)。
- 根因: 跑完 lint 之后又**新增了一个文件** (`tests/e2e/snapshot-persistence.e2e.ts`), 但提交前**没有重跑 lint** —— 那次绿是"陈旧绿"(stale-green), 不覆盖最后新增的文件。该 e2e 用 Playwright 要求的解构形参 `async ({}, info)`, 触发 `no-empty-pattern`。
- 即: 门禁结果与 staged 集合**不同步** —— 门禁是在更早的工作树状态上跑的。

## 工程师介入动作
- 修 `({}, info)` → `({ browserName: _b }, info)` (镜像其它 e2e), 重跑 lint+typecheck 绿后再推。

## 应沉淀的上下文或规则
- **提交前的门禁必须跑在"即将提交的那个工作树状态"上**: 凡在跑过 typecheck/lint/test 之后又有任何 Write/Edit (尤其新增文件), 提交前**必须对最终状态重跑相关门禁** (至少 lint+typecheck, 改了被测代码再加 test)。"我刚才跑过了"不算数 —— 算数的是"最后一次编辑之后跑过"。
- 新增**测试文件/e2e** 极易漏: 它们常在主改动门禁跑完后才补; 而 lint 规则 (no-empty-pattern / 未用 import / Playwright 形参约定) 只在重跑时暴露。
- 低成本护栏: 提交前 `git diff --cached --name-only` 看 staged 集合, 若含上次门禁后才动过的文件 → 重跑门禁再提交。
