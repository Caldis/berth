# 工程摩擦记录

task_id: GH-150 (2026-06-22-gh-150-overview-drag-ux-overhaul)
关联: memory `berth-frontend-design-taste` (dashboard 高度布局定案)

## 发生阶段
3.0-implement / 4.0-verify — dashboard widget 高度布局的视觉迭代。

## 现象
widget 高度布局来回 6 轮才定案, 中途还交付了一个明显回归:
1. 固定档 (short/tall 强制档高) → 内容矮的 widget 卡片底部大留白。
2. 加 mini 矮档 → 横条不留白了, 列表/图表仍留白。
3. 加边框 → 边框把每个矮内容卡片的底部留白全暴露 (用户: "边框一加问题就暴露了")。
4. 内容驱动 masonry (ROW_UNIT=8, align-self:start) → 卡片贴合但间距 24~31px 不等 (量化余量错位), 用户: "没收敛到整数倍"。
5. 卡片撑满 grid 占位 + 内层测量 (求整数倍可见高) → **measure 的内层被 h-full 拉伸 → span 循环放大 → stats-band 撑成超大空卡**, 用户: "你搞砸了"。
6. revert 第 5 步 + ROW_UNIT=1 → 卡片精确贴合、间距恒 24px。用户 AskUserQuestion 选定 masonry 贴合, 定案。

## 工程师介入动作
用户每轮截图反馈 (留白 / 边框暴露 / 错位 / 搞砸); 最后一轮 revert 止血后, 用 AskUserQuestion 摊开"卡片贴合 vs 同行对齐"不可兼得的权衡, 用户选 masonry 贴合, 才收敛。

## 应沉淀的上下文或规则
- **"卡片贴合内容 (无留白)" 与 "同行对齐 / 整数倍收敛" 是不可兼得的根本权衡** (masonry 给前者+错落, 行/固定布局给后者+矮卡留白)。视觉需求出现**反复打补丁** (≥3 轮同类反馈来回) 时, 先停下识别是否撞上架构性不可兼得, 早用 AskUserQuestion 把权衡摊给用户选, 别闷头调参数一版版试。
- **masonry/grid 测量改动前先在脑里跑 CSS 布局**: 确认 measure 的元素不会被 `h-full`/`flex-1` 拉伸到 grid area — 否则 `测高→算span→撑大→测更高` 循环放大。测量元素必须是自然高 (content), 不能同时是被 stretch 的卡片本体。
- **大视觉重构改完必先自验 (CDP 截图) 再交付**, 别让用户当放大镜逐版挑错; agent-dev 临时 profile 数据加载慢, 截图要等数据态 (见 memory `berth-ui-visual-verify-on-mac`)。
