## 发生阶段

4.0-verify

关联任务: GH-72 (`docs/works/2026-06-02-gh-72-cost-source-badge-details`)

## 现象

实现提交 `feat(usage): clarify cost source badges` 后, 推送前本地检查通过, 推送后运行 `pnpm harness:ci:wait` 时手动传入了错误的完整 SHA:

- 传入: `2fa6c3373cc55ffc6056ec11317106fb420ad9e8`
- 实际 HEAD: `2fa6c333de226ad9707796262047cc2a5d735c26`

结果 `harness:ci:wait` 等到超时, 报告找不到对应 CI run。随后用 `git rev-parse HEAD` 读取实际 SHA 后, `pnpm harness:ci:wait -- --sha 2fa6c333de226ad9707796262047cc2a5d735c26 --timeout 120 --poll 5` 立即确认 CI 已通过。

## 工程师介入动作

手动运行:

- `git rev-parse HEAD`
- `gh run list --repo Caldis/berth --branch master --limit 10`
- `pnpm harness:ci:wait -- --sha 2fa6c333de226ad9707796262047cc2a5d735c26 --timeout 120 --poll 5`

确认 GitHub Actions run `CI#26822959911` 对实际 HEAD 成功。

## 应沉淀的上下文或规则

CI wait 的 SHA 不能从输出里手抄或凭记忆拼写。每次 push 后必须先用 `git rev-parse HEAD` 取当前提交完整 SHA, 再把该值传给 `pnpm harness:ci:wait`。
