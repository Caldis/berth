# 工程摩擦记录

## 发生阶段

GH-97 `harness-4.0-verify` 的 Windows 视觉与窗口命中验收。

## 现象

验证原始文件查看器时, 先用 CDP 设置了 renderer viewport, 再手写 Win32 `SetCursorPos` 坐标点击右上窗口按钮。期间 dev server 因并行改动重启过 Electron 主进程, 之前记录的窗口 handle / PID 已经不是当前可见窗口。后续点击没有命中 agent-owned Berth 窗口, 反而点到桌面上其他应用, 弹出了系统 `mailto` 应用选择器。

同一轮里 `dev:agent screenshot --mode screen` 也因为目标窗口没有确认置前无遮挡, 截到了前台其他窗口内容。

## 工程师介入动作

- 用 Esc 关闭误触发的系统弹窗。
- 停止继续手写点击坐标。
- 改用现有 `tests/e2e/window-controls.e2e.ts` 覆盖真实 OS 鼠标点击命中。
- 使用 `pnpm dev:agent screenshot gh97-memory-viewer --mode print-window --json` 对当前 agent-owned Electron 主进程截图。
- 通过 `pnpm dev:agent guard after --id gh97-memory-viewer --json` 确认用户 dev server 未被停止。

## 应沉淀的上下文或规则

- dev server / Electron 主进程重启后, 任何先前缓存的 PID、window handle、窗口矩形和 CDP viewport 坐标都不能继续用于真实 OS 点击。
- CDP `page.setViewportSize()` 只适合 renderer 验收, 不应作为 Win32 `SetCursorPos` 坐标来源。
- 真实窗口按钮命中优先复用现有 e2e helper 或测试, 不临时手写坐标脚本。
- `screen` 模式截图必须先确认 agent-owned 窗口置前且无遮挡; 不满足时只能使用 `print-window` 作为窗口内容截图证据, 并在汇报中说明。

## 建议的流程改进

在 `harness-4.0-verify` 的 Windows UI 验收规则中补充: 真实鼠标点击前必须重新获取当前 agent-owned Electron 主进程和窗口 handle, 禁止复用重启前的坐标; 不要把 CDP viewport 坐标直接用于 Win32 点击。
