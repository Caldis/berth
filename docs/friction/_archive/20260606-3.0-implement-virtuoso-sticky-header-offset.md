# 工程摩擦记录

## 发生阶段

3.0-implement / 4.0-verify, GH-108 会话分组头 sticky 吸顶偏移 (tweak 1: 保留 gutter 边距)。

## 现象

用户要求 `GroupedVirtuoso` 的分组头 sticky 吸顶时保留 gutter 边距 (不贴 TopNav 顶边)。两个直觉方案实测都失败:

- **方案 A — 把 gutter `paddingTop` 从内容 div 移到滚动容器 `<main>`**: 吸顶头确实下移 (72→120), 但头**上方出现行穿透** —— 一条本属于该组的会话行画在了吸顶头之上。
- **方案 B — override virtuoso sticky 元素的 inline `top` (0→24px)**: 头钉到 96, 同样穿透。

CDP `elementFromPoint(x, mainTop+12)` 实测确认: 头钉在 96 时, y=84 处仍命中 `session-row-*`。根因: **react-virtuoso 的 item/row 是绝对定位 (transform/top)**, 不受滚动容器 padding 约束, 会画进容器 padding 带 / sticky 头上方的任何透明 gap。`scrollPaddingTop` 只影响 scrollIntoView, 不遮挡。移动容器 `paddingTop` 还会被 virtuoso 计入 sticky `top` 造成双偏移。

## 工程师介入动作

- 用 CDP `elementFromPoint` + `getComputedStyle(el).position==='sticky'` 实测每个 sticky 元素的 `inlineTop`/`rectTop` 与穿透点, 而非肉眼判断。
- 回退方案 A (app-layout 全局 paddingTop 改动净零回退), 放弃方案 B。
- 改为把 gutter 写进**分组头自身的 `pt-6` (top padding)**: 吸顶时头自身不透明 `bg-background` 覆盖 gutter 带, 绝对定位行被遮挡; flow 与 stuck 偏移一致。

## 应沉淀的上下文或规则

react-virtuoso (`GroupedVirtuoso`) 的行为绝对定位。**任何想在 sticky group header 上方留出间距的方案, 只要那段间距是透明的或靠容器 padding 实现, 都会被绝对定位的行穿透。** 可靠做法唯一: 把偏移做进 sticky header 自身的不透明 padding/box, 让 header 自己遮挡上方区域。

- 不要用滚动容器 `paddingTop` 给 virtuoso sticky 头让位 (会被穿透 + virtuoso 双计 top)。
- `scrollPaddingTop` ≠ 遮挡, 只管 scrollIntoView 落点。
- sticky 头自身圆角 (rounded-t) 同理会留透明缺口被行穿透, 故 sticky 头应方角 + 不透明背景。

## 建议的流程改进

涉及虚拟列表 sticky 视觉 (偏移/圆角/层叠), 先用 CDP `elementFromPoint` + sticky 元素 rect 实测穿透与钉点, 再下结论与选型; 不靠截图肉眼或理论推断。
