# 工程摩擦记录

## 发生阶段
4.0-verify (GH-116 真机 CDP 走查, HeroUI Select 多选弹层)

## 现象
CDP/Playwright 走查脚本里 "点 Select 触发器 → `listbox.waitFor(visible)` → 点 option" 的标准序列, 真机上 option 点击**只落了 focus 没落选中** (aria-selected 仍 false, 弹层也未被后续 Escape 关闭), 脚本据 showing 计数误报 "类型过滤未生效"。同一交互在 jsdom 测试与人手操作下都正常。

## 工程师介入动作
无 (Agent 自查): waitFor(visible) 在 HeroUI/react-aria 弹层**入场动画期间**即满足, 此时点击坐标/事件序列可能被 framer-motion 过渡吞掉。用最小交互探查脚本复跑同一序列 (多 500ms 稳定等待) 即正常: click → aria-selected=true → 计数 989→270, Space 反选, 外点关闭 — 产品行为无 bug。

## 应沉淀的上下文或规则
- 真机 CDP 走查中 HeroUI 浮层 (Select/Popover/Dropdown) 内的点击断言失败时, **先怀疑脚本时序伪影, 再怀疑产品**: waitFor(visible) ≠ 动画完成; 复核手段 = 最小交互探查脚本 + 断言 `aria-selected`/受控状态, 而不是只看下游渲染结果。
- 稳妥写法: 弹层出现后点击目标 option 前先 `expect(option).toBeVisible()` + 短暂 settle (或 Playwright `locator.click({ trial: true })` 探一次), 多选场景断言 aria-selected 而非仅计数。
- 与既有 friction 20260606-heroui-migration ("浮层改动必须本地补跑 e2e") 同族: 浮层 + 动画 = 自动化交互的首要怀疑点。
