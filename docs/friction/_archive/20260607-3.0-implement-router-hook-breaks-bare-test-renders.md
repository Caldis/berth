# 工程摩擦记录

> 关联: GH-112 (插件↔能力跨页双向跳转)

## 发生阶段
3.0-implement (给共享页面组件加 react-router hook)

## 现象
为跨页焦点契约新增 `useFocusTarget`(内部用 `useLocation`/`useNavigate`),把它接进
`Instructions` 与 `HooksLifecycleView` 两个被广泛复用的组件后, **既有渲染测试整片
报错** `useLocation() may be used only in the context of a <Router> component`:
- `instructions-guidance.test.tsx` 两处 `render(<Instructions/>)` 裸渲染未包 Router → 失败。
- `hooks-lifecycle-view.test.tsx` 全部 29 个用例的 `renderHooks` 未包 Router → 全红。

## 工程师介入动作
给这些测试的 render 包 `<MemoryRouter>`。组件在真实 app 里恒在 Router 下, 故这是
测试侧补齐, 非产品 bug。

## 应沉淀的上下文或规则
- **给一个被多个测试"裸渲染"的共享组件新增任何 react-router hook
  (useLocation/useNavigate/useParams/useSearchParams) 前, 先 grep 它的所有测试
  render 点, 一并补 `<MemoryRouter>`**; 否则会出现与改动看似无关的整片测试红。
- 本任务另外两个相关实现陷阱 (一并记下供复用):
  1. **嵌套 button 非法**: 卡片 header 本身是 `<button>`(展开切换)时, 不能把可点击
     徽标 button 嵌进去; 应作为 toggle button 的**同级** (flex 行); 纯 div 行才可内嵌。
  2. **消费型焦点 state 的测试**: `useFocusTarget` 读 `location.state` 后立即
     `navigate(replace, state:{})` 清除; 因此断言"跳转携带了 focus state"必须让
     **目标路由渲染一个不带 useFocusTarget 的 probe** (用 `<Routes>`), 否则同页的
     useFocusTarget 会在断言前吃掉 state。

## 建议的流程改进
(由 harness-5.1-friction 消费) 在 implement checklist 加一条: "给共享/页面级组件引入
router hook 时, 同步审计并修复其所有裸 render 测试 (包 MemoryRouter)"。
