## 用户原话
> 请你从常规用户的角度来思考这里的功能逻辑和策略, 全局就是用户设备上所有能被扫描出来的资产, 用户域为独立在项目以外的公共的那些资产, 项目域则保持现状。
> /goal 对这里的 scope 特性做出完整重构和模块功能收敛, 和前面的流程一样与 codex 进行两次交叉 review 并落地改造。
> 部分 scope 的资产会有重复扫描的问题, 请顺带解决。

## 解读 (重定义作用域语义)
- **全局 (global)**: 用户设备上**所有能被扫描出来的资产** = 所有项目 + 用户级 + 企业级。当前实现只显示"当前项目 + 用户级", 需改为聚合所有(会话派生且仍存在的)项目。
- **用户域 (user)**: 独立在项目以外的**公共/用户级**资产 (~/.claude, ~/.codex 等用户级配置, 不含任何项目级)。
- **项目域 (project)**: **保持现状** (当前所选项目 + 继承链)。

## 顺带修复: 重复扫描
- 现象 (截图 #10): `D:\Code\react-zmage\AGENTS.md` 在项目域出现两次 (同名同路径)。
- 根因 (待 explore 核实): `AGENTS.md` 是 Claude Code 与 Codex 共享约定, claude-code 适配器与 codex 适配器各扫一次 → 同一物理文件两个资产。

## 范围
- 重定义三档 scope 语义 + 收敛分散 scope 逻辑到统一模块 + 去重同一物理文件。
- 流程: Codex 两轮交叉对抗 review (设计+实现) 后落地, 同 GH-111。

## 约束
- 全局聚合所有项目 → 性能 (只扫仍存在目录 + 去重 + 缓存); 官方语义须英文查证 (CLAUDE.md/AGENTS.md 各 agent 读取与作用域归属)。

## 验收
- 三档 scope 符合重定义; 无重复条目; scope 逻辑收敛统一模块; 秒级切换不退化; 全测试 + Codex 两轮 review 闭环。
