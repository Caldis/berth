> - 首页类似 Codex 增加一些统计信息 (参考图: codex-style-stats.png)
> - 也可以类似 github 增加 activity 和马赛克 (参考图: github-activity-heatmap.png)
> (并调用 /frontend-design 技能)

**轮 2 — 扩展为模块化可配置:**
> 不仅限于我提的这些, 你也可以尽可能丰富首页, 增加更多形态和风格的信息可视化, 并让首页成为一个模块化, 可配置内容的动态区域, 丰富用户的 onboarding 体验. 为此你需要准备各种可视化小组件和各种信息以及维度的组合, 并用高级的审美和布局来提高用户的体验, 以高品位高格调交付, 注重设计细节.

## 正文 (结构化需求)

### 1. 健康检查弹窗化
- 当前健康检查 worklist 在首页平铺占位 → 收拢到弹窗。
- 入口为可点击的警告/状态指示; 点击弹出健康检查详情。
- 弹窗交互完整: open / focus / dismiss / 键盘可达 (按外部 UI primitive 行为契约)。

### 2. 可视化 widget 库 (多形态多维度)
准备一组形态各异、风格高级的可视化小组件, 覆盖不同信息与维度组合, 至少包括:
- **指标卡 (Codex 风格)**: 累计 Token 数、峰值 Token 数、最长任务时长、当前连续天数、最长连续天数等。
- **活动热力图 (GitHub 风格 mosaic)**: 年度贡献/活动方格图 + 颜色深浅梯度 + 时间维度切换 (每日/每周/累计)。
- **活动洞察**: 快速模式占比、最常用推理强度、已探索技能数、使用技能总数、会话总数等。
- **排行/列表**: 最常用插件、最常用技能、最近会话等 Top-N 列表。
- 其它趋势/分布形态 (折线、柱、占比环、分布) 视数据可得性补充。
- 所有数据真实来自已扫描资产聚合 (session / token / skill / plugin / agent), 非 mock。

### 3. 模块化 widget 系统
- 首页区域由可插拔 widget 组成, 不是固定平铺。
- widget 之间解耦, 各自声明数据需求与渲染; 便于后续新增 widget 与跨页复用。
- 架构强调可维护性、可扩展性、组件复用。

### 4. 完全自定义布局 (拖拽 + 缩放)
- widget 支持**拖拽改变位置**。
- widget 支持**调整大小** (resize)。
- 支持完全的自定义组合 (增删 / 显隐 / 排列 / 尺寸)。
- 布局/配置**持久化** (跨会话保留用户自定义)。

### 5. 高性能
- 首页性能要求极高: 拖拽 / 缩放 / 多 widget 同屏渲染无卡顿。
- 数据聚合不阻塞 UI; 大数据量 (年度热力图、海量 session) 下保持流畅。

### 6. Onboarding 体验
- 丰富首次 / 空数据体验, 引导用户认识可用信息与能力。
- 空态 / 默认布局 / 引导应被设计为体验的一部分, 而非占位。

### 7. 交付品质
- 高级审美与布局, 高品位高格调, 注重设计细节 (frontend-design 方法论)。
- 完整状态设计: 加载 / 空 / 错误 / 禁用 / focus / 拖拽中 / resize 中。
- 响应式与可访问性。

## 验收方向 (供 design/verify 细化)
- 健康检查收拢为弹窗, 首页不再平铺该区块。
- widget 数据真实聚合自资产; 时序/多源可视化按 harness 不变量 22 真跑观察 (CDP 时序), 不以 unit+CI 静态绿代替。
- widget 可拖拽、可缩放、可增删显隐, 配置持久化且重启后保留。
- 首页交互在多 widget 下保持流畅 (性能验收)。
- 架构支持低成本新增 widget (可维护 / 可复用 / 可扩展)。
- 主观视觉 / 布局 taste 由用户最终裁定 (verify 先截图确认)。
