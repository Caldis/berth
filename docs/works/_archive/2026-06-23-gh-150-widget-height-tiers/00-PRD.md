## 背景

GH-150 第一轮「拖拽 UX 大修」已 archive (`docs/works/2026-06-22-gh-150-overview-drag-ux-overhaul/`)。其布局结论收敛为「同行等高 uniform grid」(grid items-stretch + 卡片 h-full), 并**移除**了原计划的高矮档 (short/tall, 中途因「切换无实感」删除 commit ba999735; 见 `docs/friction/20260622-3.0-implement-dashboard-height-iteration-tradeoff.md`)。

但 #150 原始 PRD 第 4 点本就要求「所有小组件应该有几组固定高度和宽度…固定的整数倍」。本轮回归该诉求, 但**修正语义**: 上次失败根因是「高度」是错误的输入维度 (用户调高度档只看到卡片变高、内容没变、留白变多 → 无实感)。本轮把用户可调的维度从「卡片多高」改成「看多少内容」, 高度变成内容撑出的结果。

## 正文

### 用户诉求 (原话, 2026-06-23, 按时间序)

1. 起始:
> 高度应该要有预设 (三档), 但只有部分小组件能暴露给用户设置。请分析每个小组件的设计, 确定哪些要暴露, 哪些要固定。

2. 改变方向 (要更发散的方案):
> 不要继续读了, 我现在改变主意了, 我希望你给出更多的方案, 综合考虑 高度的处理、现状的小组件、拖拽的逻辑等等, 提出一些更有想象力的方案, 当然要符合实际, 我会和你一起评估这些方案, 选择一个继续。

3. 补充硬约束 (附截图: 当前概览顶部 stats-band 指标带 — 累计 TOKEN / 单日峰值 / 最长任务 / 当前连续 / 最长连续 + sparkline):
> 你需要确保有一档高度是和现在这个 [概览] 的小组件高度适应的。

### 用户已确认决策 (AskUserQuestion, 2026-06-23)

- **方案方向 = 内容密度档 (Content tiers)**: 三档调的是「内容量」(列表行数 / 图表高度+细节) 而非空间高度, 直接根治前一轮「切换无实感」根因。
- 否决: Resize 自由缩放 (打破等高) / 二维自由网格 (需重写布局层, 对 berth 过度) / 全局密度模式 (非 per-widget)。

### 关键约束 (用户明确, 最高优先级)

1. **H2 ≡ 现状**: 每个 widget 的标准档以「当前渲染成什么样」为基准, 不另造像素值; catalog 全员 `defaultSize.h='H2'` → 默认布局 (全 H2) 对当前截图**像素级零回归**, 概览不变样。
2. **部分暴露**: 有内容弹性的 widget 暴露高度切换; 内容固定的 widget 固定单档、不渲染切换器。
3. **三档定位**: 现状 = 中间档 H2; H1 更紧凑, H3 更多/更高。`heights` 每 widget 声明支持子集, 但**必含 H2**。
4. **图表 H2 零回归**: 图表类 H2 保持当前 `chartHeight` 原值原行为; 「填满等高消留白」降级为 H3 行为, 不进默认档。

### 验收意图 (待 design 细化为可测条目)

- 默认布局 (全 H2) 对当前概览**像素级零回归** (实测窗口坐标裁剪比对; 见 AGENTS.md BUILD_ENV 截图规范)。
- H1/H3 各 widget 内容密度**肉眼可分** (逐组件 × 逐档 CDP 截图; _shared 不变量 22)。
- 固定类无高度切换器; 弹性类切换器可用且选择持久化进 layout。
- 切换档位 / 拖拽时 framer layout 高度过渡平滑, 无内容变形。
