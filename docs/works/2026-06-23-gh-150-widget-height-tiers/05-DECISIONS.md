# 05-DECISIONS — 决策演变日志

本任务设计 2026-06-23 多轮对话经历多次质变。记录每个转折的"为什么", 防未来重走弯路。光看最终 SPEC 无法理解为什么是混合模型 —— 这是本任务长期价值最高的文档。

## 转折1: 内容密度档 → 完全自定义 dashboard
- 起点: 用户要"高度三档预设, 部分 widget 暴露"。产出 01-ANALYSIS (16 widget 弹性分级) + 内容密度档 (H1/H2/H3 手选)。
- 转折: 用户澄清真实目标 = "完全自定义、任意拼接组合的 dashboard, 持续加丰富小组件"。
- 为什么: 离散三档手选满足不了"任意拼接无缝" —— 数学上只有 row-based 整数倍网格 (引擎) 一个解。内容密度档退化为引擎的"层2 内容自适应", 没废弃。

## 转折2: 全数值12列 → 宽度档保留的混合
- 中间 (v2): 全数值 span (w,h 都 1-12), 12 列, 删 WidgetWidth。
- 转折: 用户问"宽度预设是否保留"。采纳混合: 宽度档 (W1/W2/W4) 保留 + 高度数值 span。
- 为什么: 宽高性质不同。宽度受响应式断点强约束 (窄屏降列) + 耦合内容布局 (W1 简版/W2 完整离散), 好宽度只有少数几个 → 预设档。高度纵向无约束 + 随高连续 → 自由 resize。混合还保留 berth 现有响应式宽度系统, 改动小得多、风险低。

## 转折3: react-grid-layout → 自研 CSS Grid
- 为什么: 查证 RGL 2.x 残留 react-draggable ^4.4.6 (依赖 React19 已移除的 findDOMNode) + react-resizable 等 4 遗留 dep; peer react>=16.3 无上限不声明 React19。berth=React19 不押兼容赌注。CSS Grid (span+dense) 原生零依赖; dnd-kit 已在用。RGL"动态内容高度要手动重算"对混合模型不适用 (高度驱动内容)。

## 转折4: "另起炉灶"纠偏 → 分层架构
- 失误: Agent 反复把"布局引擎"和"内容方案"当互斥, 推翻前者。用户纠正"不要总是另起炉灶, 应该融合"。
- 修正: 两层。层1 引擎 (widget 占多大格子)。层2 内容自适应 (格子里显示什么: 列表行数=f(h)/图表填满/固定类锁定, 复用并推广 01-ANALYSIS)。上下游非替代。详见 friction。

## 当前生效设计 (v3)
混合 dashboard 引擎: 宽度档 (W1/W2/W4 响应式列, 保留) + 高度数值行 span (resize) + grid-auto-flow dense 填空 + 两层 (引擎/内容自适应)。契约与落地详见 02-SPEC v3 顶部。

## 仍未定 (CDP 校准)
