# harness-5.1-friction — 流程摩擦收敛

目标: 消费 `docs/friction/` 的经验, 把可复用流程经验写回规则。

步骤:
1. 阅读 `docs/friction/` 下未归档的摩擦记录。
2. 归类: 哪些应固化为 `.agents/workflow/*.md` 的步骤改进, 哪些应补进 `.agents/tools.md`
   或 `docs/ARCHITECTURE.md`, 哪些应补成新的 skill。
   - 折叠判据 (EVOLUATION canonical): 只把高复发/高影响的折进常驻 playbook; 一次性、低复发的归档即可 — 规则越堆越长则无人逐条读。
3. 修改对应 playbook / 文档 / 工具脚本。
4. 改进对应的摩擦记录移入 `docs/friction/_archive/`。
5. 若改动了分发产物的生成逻辑, 运行 `pnpm harness:sync`。
6. **可选修剪 pass (2026-07-04, 定期或不变量数破阈值时)**: 对 `_shared.md` 与各 playbook 做逐**句** no-op 测试 — "这句相对默认行为改变了什么?" 改变不了的整句删除 (不是删词); 同一规则多处复述的收敛到 canonical 单处, 其余改引用。沉积 (sediment) 是无修剪纪律 playbook 的默认命运: 加规则显得安全、删规则显得冒险, 于是只增不减直到无人逐条读。

产出: 已处理的一组 friction 记录和对应规则改进。
