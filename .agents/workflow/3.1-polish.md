# harness-3.1-polish — 抛光 (Polish 阶段)

目标: 在当前任务已经通过 verify 后, 由用户决定是否继续深挖当前任务范围内的可改进点。

前置:
- INDEX.phase == verify 或 INDEX.phase == polish。
- 已存在 01-ANALYSIS.md, 02-SPEC.md, 03-PLAN.md。
- 只能由用户主动要求, 或 Agent 在复杂任务 verify 后询问并获得同意后执行。Agent 不得自行进入本阶段。

步骤:
1. 若用户未明确同意, 停止并询问是否执行抛光; 不得继续。
2. 将 INDEX.phase 置 polish, 确保存在 04-POLISH.md。
3. 读取 00-PRD.md / 00-BUG.md, 01-ANALYSIS.md, 02-SPEC.md, 03-PLAN.md 与本任务变更文件。
4. 明确当前任务边界:
   - 当前任务负责的功能、文件、测试与验收标准。
   - 不属于当前任务的旁支问题。
5. 只在当前任务边界内检查:
   - 是否有可继续深挖的正确性问题。
   - 是否有交互和视觉可优化点。
   - 是否有可用性、应用性、错误态、空态或文案问题。
   - 是否有性能、加载、资源占用问题。
   - 是否有测试覆盖或验收证据缺口。
6. 将候选项写入 04-POLISH.md, 按影响和成本排序, 标明是否建议进入当前任务, 并记录预计增加或偿还的 debt point。
7. 不自动改代码。向用户确认:
   - 跳过全部: INDEX.phase 回到 verify, 下一步 archive。
   - 选择部分项: 将选中项追加到 03-PLAN.md, 修正 INDEX.md `debt.estimate` 并追加 `debt.revisions[]`, INDEX.phase 回到 implement。
   - 发现越界问题: 记录到 docs/issues/, 当前任务只交叉引用。

产出: 04-POLISH.md 与用户选择结果。无用户确认不得新增实现改动。
