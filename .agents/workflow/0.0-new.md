# harness-0.0-new — 启动新任务

输入: 任务描述 + 可选 GitHub Issue 引用 (`GH-123` / `#123` / issue URL, 参数 $ARGUMENTS)。

步骤:
1. 读取 `.agents/workflow/_shared.md` 的命名与状态契约。
2. 确定任务类型 (`feature | bug | maintenance`)、priority、source、SUMMARY (kebab-case) 与初始 debt estimate。
   - maintenance 必须填写 `maintenance.subtype`; `issue` / `friction` 只写入 `source.kind`, 不作为 subtype。
   - 初始 debt 可以保守估算; explore/design 发现影响面变化后必须修正并追加 `debt.revisions[]`。
   - 如果用户没有明确指定 feature/bug, 先运行 `pnpm harness:stats`; 若输出 `maintenance=<subtype>:<score>`, Agent 默认创建 `type: maintenance` 且使用该 subtype。
   - 自动选择规则由 `_shared.md` 定义; `docs` 优先于 `architecture`, 且 `architecture` 只有自身 area debt `>=40` 时可自动选择。
3. 绑定 GitHub Issue:
   - 若输入已有 Issue 引用, 用 `gh issue view` 读取真实 `number` / `url` / `id`。
   - 若没有 Issue, 用 `gh issue create` 创建仓库 Issue, 标题取任务标题, body 记录来源摘要。
   - 若 `gh` 缺少权限或无法确定 Issue, STOP; 不进入 explore。
4. 计算 `task_id=GH-{issue_number}` 与目录名 `{今日YYYY-MM-DD}-gh-{issue_number}-{SUMMARY}`, 在 `docs/works/` 下创建。
5. 从 `docs/works/_template/` 拷贝模板:
   - 公共: INDEX.md, 01-ANALYSIS.md, 02-SPEC.md, 03-PLAN.md
   - feature / maintenance 拷 00-PRD.md; bug 拷 00-BUG.md
6. 填写 INDEX.md frontmatter: task / task_id / type / phase=explore / created / priority / source / debt.estimate / issue。
7. 若有 PRD/BUG 来源, 将原始内容快照写入 00-PRD.md 或 00-BUG.md。
   - **多批次计划的输入全量前置快照** (2026-07-04): 若本任务是某个跨会话多批次计划的一批, 建批次一时就把**全部批次**的原始输入落盘 (每批一个 docs/issues 条目或统一清单文档), 不等轮到该批才快照 — 会话压缩会丢掉只存在于对话里的批次输入 (审查批次曾靠转录考古救回)。
8. gh project 跟踪 (见 .agents/tools.md 的 scope 前置):
   - scope 探测**以真实能力为准**: 先 `gh api graphql -f query='{viewer{projectsV2{totalCount}}}'`。成功即 token 有 project 访问能力 —— 此时 `gh project list` 报 `missing required scopes` 只是 gh CLI 客户端 scope-gate 假阴性 (见 friction `20260621-0.0-new-gh-project-scope-gate-false-negative`), **不判 pending-auth、不 STOP**; 若 `harness-projects.mjs` 的 `gh project` 子命令仍撞 gate, 直接给固定命令 `gh auth refresh -h github.com -s project,read:project` 让子命令通过断言 (浏览器授权, Agent 不可代办), **不抛多选问题、不提供"跳过 task-state / GitHub 跟踪"等违反 harness 的选项**。
   - 仅当 `gh api graphql` 也失败 (真实无能力) 时才 STOP / 置 `blocked` + `pending-auth`, 提示上述 refresh 命令; 授权后重跑本步。
   - 若任务目录已经创建, 但本步因缺少 Project scope 无法继续, 将 INDEX 置为 `phase: blocked` 且 `gh_project.status: pending-auth`; 不得填 `item_id: TBD` 之类占位值。
   - 可用时先运行 `node scripts/harness-projects.mjs fields ensure`, 再运行 `node scripts/harness-projects.mjs ensure docs/works/{task}`。
     - 非本地门禁可由子代理执行: Project fields/ensure 可交给子代理或后台 agent 处理; 主 Agent 必须消费成功结果, 确认 INDEX.md 回写真实 `PVTI_...` 后才可进入 explore。
   - 当前用户仓库使用 Project 自定义字段 `Task Type`, 不写真实 GitHub Issue Type。
   - **gh node id (project/item/field/option) 一律从 `gh --format json` 输出取真实 id; 严禁手敲或凭记忆填**。
   - 确认 INDEX.md 已回写 `gh_project.item_id` 和 `item_status: In Progress`, Project 已同步 Task Type / Priority / date / debt / scope / risk / source。

产出: `docs/works/{task}/` 初始化完成, phase=explore, GitHub Issue 与 Project item 已绑定。
完成提示用户: 下一步 `harness-1.0-explore`。
